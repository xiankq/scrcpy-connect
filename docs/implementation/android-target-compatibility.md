# 被控 Android 兼容边界

本文件区分被控系统、ADB 协议能力和主控安装条件。被控基础远控以 Android 5.0／API21 为下限；这不表示所有扩展功能均从 API21 可用。主控最低版本由各 runner 和 Flutter／播放器依赖决定，不随被控下限降低。

## 功能条件

| 能力 | 条件及处理 |
| --- | --- |
| ADB 连接 | 协议版本、maxdata、feature 分别协商；无 feature 的旧 adbd 仍可连接。传统 TCP 使用明确 IP 和端口；现代配对要求被控提供对应协议 |
| 整机画面与触控 | API21 起；编码器、显示捕获及厂商输入权限在实际启动时确认。编码失败报告具体原因，不伪装成主动取消 |
| 独立应用窗口 | API29 起；不可用时不影响整机远控 |
| 设备输出声音 | API30 起；Android 11 启动捕获时还受锁屏条件约束。播放所有权仍由实际打开的控制页面决定 |
| 文本剪贴板 | API21 起；按实际 Binder／AppOps 权限确认。自动同步仍是设备设置，关闭时不自动覆盖主控剪贴板 |
| 文件浏览、搜索与传输 | 使用实际授权身份；目录、元数据失败及数量上限必须显式返回。无权目录不表示空目录 |
| 图片缩略图及源身份校验 | API21 起；保持采样、EXIF 八方向、有界独立进程、超时与取消清理 |
| 视频缩略图 | 当前有界实现要求 API27；较低版本明确返回尚未实现，可主动打开原件，不下载原视频伪装缩略图 |
| 通知与通话观察 | 按接口及权限单独确认。AOSP API21 的 shell 缺少相关系统权限，应显示受限；不授予额外权限绕过 |

SDK 条件成立只表示允许尝试。连接成功、接口存在、启动命令已发出和实际功能可用分别判断；一个扩展功能受限不应断开整台设备或禁止其他入口。原子“不覆盖”重命名还取决于内核与文件系统支持，无法保证时拒绝操作，不用删除／复制组合冒充原子提交。

## 旧协议与文件服务

`interop-adb` 保留经典 1.0.0 的求和校验、OPEN 终止零字节和按协商容量分片；AUTH 授权等待可在总时限内响应 framework 再次发出的 TOKEN。兼容旧 adbd 的零发送方 ID 关流，单流结束不取消整条连接；reverse 关闭前排空已接收尾包。

经典 shell 的退出码保持未知。需要确认文件变更结果时，使用原始执行通道的独立退出回执；回执丢失表示结果未知，不自动重试。基础操作不依赖设备存在 `printf`、`stat`、`find`、`sha256sum` 或 `toybox`。

无 `stat_v2` 时，元数据使用同一个临时原生文件服务，保留 64 位大小和真实 errno。浏览、传输前后源校验、目标冲突检测及原件预览使用同一元数据边界，不能在提交前重新读取会截断大小的旧 STAT。无 `ls_v2` 时也使用它枚举目录，因为旧 LIST 会将无权目录报告为空并静默跳过部分错误条目。支持 v2 的设备保留 SYNC 快路，系统策略拒绝时使用相同文件服务处理，不另建旧版服务端。

文件服务通过已打开的目录描述符枚举，子项不跟随符号链接；只有明确的 Android 主共享存储根别名可解析。文件浏览与树任务单目录最多 10000 项，搜索／图库单目录最多 4096 项；截断和单项失败不能被计为完整成功。搜索／图库的总预算仍由各自任务控制。

部署使用独占目录和已打开的可执行文件描述符。创建者通过原始通道持有目录租约，仅在独占创建成功后承担清理责任；创建回执丢失、取消或丢弃 future 时，通道 EOF 仍能触发清理，碰撞目录不被删除。主控核对回读字节与本地固定产物完全相符后才发送一次性执行授权；后续执行同一 inode。每次操作有总时限，正常释放等待受独立短时限约束。此边界不防 root 或同 shell 身份直接修改 inode。

## 服务端与资源回收

屏幕、声音与编码查询使用同一固定 scrcpy 版本；来源、标准 Java 库脱糖及对应许可见 [vendor](../../servers/vendor/README.md)。上游 Java 源与控制协议保持一致，不按 Android 版本选择另一份服务端。协同 JAR 和原生文件服务均以 API21 构建，来源与摘要见各自清单。

旧 adbd 的原始执行通道没有 PTY HUP 保证。屏幕、声音和协同服务使用同一个进程监督器，显式观察主控输入 EOF，结束其拥有的子任务，等待退出后删除临时 JAR；尚未完成媒体 socket 握手时也适用。屏幕启动先报告子进程 PID／starttime，再允许 Java 输出，后续仍验证实际进程身份。主动取消与观测到的远端关闭分别记录，普通警告日志不能把主动取消改为设备故障。图片 worker 独立观察父进程 EOF 和截止时间；取消必须确认退出后才回执。adbd 已以 root 运行时，Java 服务先降为 shell UID 再建立 Context／Binder，不要求被控 root。

## 验证证据

2026-10-19 使用固定 SDK 镜像和项目 Rust 主机验证；官方 adb 仅作独立部署、检查和对照，不进入生产调用链。

| 环境 | 实际证据 |
| --- | --- |
| Android 5.0.2／API21 x86_64 | 剪贴板往返及另一互联服务更新；EXIF 1–8、缩略图缓存与源变化校验；原生元数据、原始文件名、悬空链接、数量截断；文件创建／失败回执／浏览／删除；原始执行 EOF 清理顺序 |
| Android 6.0／API23 x86_64 | 实际 H.264 会话、认证帧边界和 FFmpeg 首帧解码 |
| Android 16／API36 x86_64 | 最终共享监督器的 H.264 首帧解码；画面／声音尚在 accept 阻塞时，EOF 后确切 Java 与 CleanUp PID、socket、JAR 均释放；创建租约后的真实元数据与文件操作；目录上传下载、空目录／空文件、冲突、取消、源变化及符号链接四组场景 |
| 协议夹具 | 真实 1.0.0／4096、无 AUTH／签名 AUTH、重复 TOKEN、零 ID 关闭、校验错误、70KB sync 分片及 reverse 背压尾包 |
| 文件与运行时夹具 | 旧 STAT 截断而原生服务返回超过 4GiB；目录错误、全局计数和快照预算；创建回执丢失的取消／超时／丢弃、目录碰撞保留；mksh 监督器退出状态、EOF、停止任务及描述符隔离；API21 进程、Binder、AppOps 与平台字段兼容 |

API21 镜像的 H.264 编码器同时无法完成系统 `screenrecord`，因此该样本未证明完整视频远控；不能由它推导所有 Android 5 手机不支持，也不能把较低版本支持写成已全面验收。API21 实际执行了 scrcpy 编码重试涉及的 Java 接口与尺寸约束计算。物理 USB、32 位 ARM 旧手机、厂商 ROM、长时间稳定性及其他主控宿主仍需要分别验证。

来源比较与固定源码证据见 [ADB 兼容研究](../research/adb-android-compatibility.md)。可复验的用例保存在 `crates/adb/tests/legacy_transport.rs`、`crates/interop_core/tests/remote_helper_android.rs`、`media_thumbnail_android.rs`、`scrcpy_device.rs` 及 companion 部署测试中；环境变量与忽略条件在对应测试声明。
