# 事件中断后的状态核验

本文规定应用业务所有者内事件中断后的核验屏障，职责以[架构](architecture.md)为准。应用打开账本的重建恢复见[应用打开记录与恢复](app-launch-recovery.md)；当前生产切换和已验证范围见[本轮重构记录](architecture-refactor-validation.md)。产品恢复行为以[交互规则](../../designs/prod/interaction-rules.md)为准。

## 边界

应用事件所有者在更新业务投影并发布事件时分配递增 `sequence`。通用能力可以维护独立的原生事件序号和有界观察队列，应用在核对所属连接、捕获及代次后采纳事实，不能混用两层水位。能力观察出现缺口时，由包的公开 Dart 接口报告需要重新核验，不把 FRB 类型或原生订阅细节交给应用。

`state.snapshot` 归应用命令所有者，只组合已加载的设备记录、偏好、文件任务、会话、音源、活动、分享状态与现有 companion 缓存，不连接设备、不新建播放器、不启动观察进程。快照携带应用发布水位；通用 Rust 层不保存平行的产品快照或分发 `state.snapshot`。核验期间出现新缺口或快照落后于已观察事件时，`StateRecovery` 最多重读四次，仍不稳定返回 `state_busy`。视频帧遥测不推进业务状态水位，避免持续视频使核验饥饿。

此屏障只核验应用已经观察到的状态，不能证明跨 Android 系统服务的远端事务。companion 查询先更新所属连接的当前缓存再返回，读取缓存不额外发布 changed 事件；取消的观察不暴露旧可操作缓存。偏好事件只引用已提交的版本；分享事件从当下所有者重新取值，已消费来源只触发重新核验。

## 应用命令与页面

`state.reconcile` 是应用 Dart 命令，由 `StateRecovery` 合并并发核验。开始立即发布本地 `state.resync` 并禁止新输入、媒体启动及通知/通话动作，也禁止新的连接、配对、唤醒、连接配置、文件变更与传输启动或续传。命令责任表 `protocol/commands.json` 以 `requiresVerifiedState` 声明该要求；精确 session UUID 的 UP/CANCEL、读取、暂停、取消与明确断开仍可处理已有活动。快照校验失败或超时后保持待核验，不把空结果当成全部结束。

公共请求在连接准备与重连意图钩子之前检查屏障，未受理命令不能撤销旧尝试或恢复自动连接意图；进入实际分派时再次检查。核验期间完成的停止不等待额外快照刷新；停止收尾先等待刷新、随后才开始核验时，也须立即解除该命令的刷新等待，原刷新仍由重连所有者接收结果。重连所有者保持未知，直到 `state.resynced` 交付权威快照；核验失败不会恢复准入。

读取前捕获本地播放器所有者，只清理快照里不存在或已结束、且读取期间未被替换的同一所有者。合并时仅允许当前播放器补充纹理、尺寸和实际解码证据，不能让旧呈现回执覆盖应用业务所有者的暂停等状态。成功发布 `state.resynced`，拒绝水位之前的旧事件；核验期间又有缺口或更新超过快照则重读。

AppController 在同步通知页面监听器之前落地不可变快照，校准 SessionViewRegistry，并废弃旧设备、设置、分享请求及旧设置保存回执。远控立即停止新输入，清理原会话触点；成功后只核对原 UUID，可见窗口确认新像素后恢复，不可见窗口维持暂停。不存在的窗口清除 Texture 并提供“重新检查”，该动作只调用核验命令，不创建替代窗口。旧导航/文本等初始动作不再执行。终态同步失效正在等待的恢复 epoch，迟到成功回执与输出事件不能解除终态暂停。

剪贴板取消旧轮询、旧队列及晚到的系统读回；前台且目标可用后重新建立当前对象基线，后台不读取。首次核验后，自动 `notifications.list/calls.list/clipboard.get` 使用 `allowStart:false`；已有观察仍可查询。无观察时返回 unknown、stopped或observation_required；列表不再启动观察，用户明确核验须调用`observation.start`，随后等待事件/status确认。`allowStart`只控制共享helper资格，不能替代观察意图。

## 编码会话边界

连续 reset 可在首个关键帧前产生多组 session/CSD。Rust `VideoPackets` 遇到新尺寸标记即清除上一段尚未成帧的配置，只合并当前段；等到关键帧后配置原生 packet source，再交付压缩包。配置容量、64 单元与完整包期限仍有界；当前路径不经过 HTTP relay 或容器封装。

## 通知与系统提醒

通知页不保留回复草稿或回复提交状态；权威恢复只刷新当前有效通知、打开与清除能力，不恢复旧动作。主控系统提醒在事件缺口时精确撤回；权威快照形成安静基线，旧 payload 不授权远端动作。平台发布、点击与冷启动边界见 [系统提醒](system-notifications.md)。

## 应用打开与初始动作

START_APP 在编码或渲染失败前可能已经产生真实任务副作用。提交边界先登记固定操作身份；后续失败保留 unknown 并取消捕获，视频输出清理不删除该记录。快照尚未绑定 sessionId 时也按设备与包名保护未知结果。手机主屏与独立窗口共用未决记录门禁，不能通过另一入口绕过。

应用持有的私有账本在业务所有者重建时将 pending/observed 保守转为 unknown；明确关闭只结束记录和所属控制资源，保留真实应用任务。排队启动在提交许可撤销后不能因迟到 ACK 再发送。详细状态和上限见[应用打开记录与恢复](app-launch-recovery.md)。

尚未提交的页面初始动作在启动期间进入后台时保留于该页面；回到前台且确认可输入后只提交一次。提交前消费意图，回执丢失不自动重发。迟到输出、前后台切换和核验成功均不能解除未知启动保护。

## 验证范围

回归核对有界队列缺口、独立观察者、快照水位、晚到设置与分享事件、companion 查询/通知交错、取消缓存、同 ID 的呈现恢复、失效所有者清理、超时/取消、输入释放、覆盖页面返回及剪贴板冻结。真实 Android 流程通过 `app/integration_test/state_recovery_test.dart` 调用应用的显式核验入口；主机队列溢出夹具不替代设备恢复。执行结果、命令及截图见[验收记录](validation.md)。

旧 Rust Runtime 的历史回归不能作为应用 Dart 业务切换后的验收。断网后的用户意图恢复、Android 杀进程/系统停止、后台通知权限与锁屏、资源仲裁、完整文件恢复和各宿主整包运行分别记录证据，不能从协议或模块测试推定完成。
