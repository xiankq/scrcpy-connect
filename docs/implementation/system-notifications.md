# 主控系统提醒

系统提醒与被控通知访问、后台保持是三项独立条件。主控不需要开启调试；被控仍由临时观察进程提供当前状态，无需安装产品APK。控制器进程死亡后不保证继续观察。

## 所有权与发布

`SystemNotificationCoordinator`由生成的keep-alive provider拥有，订阅AppController逐事件流。策略在共享Dart，`LocalNotificationSink`仅用固定版本`flutter_local_notifications:22.3.2`调用系统；没有新增Kotlin通知业务或保活服务。App根部同步处理生命周期回调，不能等待下一帧才改变后台发布资格。

`observation.changed`建立观察代次及首份快照基线；旧通知不因连接或重新核验而成批提醒。后台的新通知与变化按设备、观察代次及远端逻辑key更新同一本地项，id/revision用于点击时重新核验。仍在响铃的来电使用独立渠道，结束或替换后撤回。通知和来电提醒均不执行原动作，不自动接听、打开远控或启用麦克风。

来源移除、失去实时资格、停止观察、断开、原生停止或事件缺口都撤回相关本地项。权威恢复快照形成安静基线，未知或迟到事件不能恢复旧所有者。截断快照缺项不表示远端已删除；保留容量发生淘汰时，先撤回其系统项再丢弃索引。发布与撤回串行，已开始的发布完成后仍要执行其排队撤回。

被控快照包含系统`GROUP_SUMMARY`元数据。汇总项仍保留在实时通知列表及原应用入口，但不另发系统提醒，避免Android自动汇总在子通知之外额外提醒一次。

当前索引上限为32个设备、每设备1000个通知/32个呼叫、128个本地提醒；本地ID仅用100000–199999，排除既有连接通知2101。系统本身的通知数量限制、汇总及高负载提示仍需单独验收，不能据此承诺任意数量的逐条投递。

## 隐私、权限与点击

系统只收到“设备有新通知／设备有来电”和“请打开邻接查看”。远端联系人、号码、设备自定义名称、通知标题、正文、验证码、附件及回复草稿均不进入系统内容或payload；payload只有版本和对象定位标识。应用不建立通知历史，也不声称系统通知从不落盘。

`notificationAlerts`和`callAlerts`分别持久化，默认开启提醒意图；系统权限只在明确操作时请求。初始化不会弹权限窗口。后台页分别显示整体权限和渠道关闭状态，关闭提醒不会停掉观察或连接。提醒发布请求成功不等于用户看见或读过。

运行回调和启动payload先入有界待处理队列；待初始化、前台、路由及权威状态就绪后再核对设备、观察代次和对象revision。有效点击只进入对应设备的通知或通话专用页；失效对象显示失效说明，不执行旧通知动作、启动连接或创建远控。相同payload只消费一次。

新进程先保存启动payload，再只清理本命名空间内的旧提醒；不用`cancelAll`，不误删连接通知或其他所有者。进程恢复活动及冷启动系统交互仍须独立验证。

## 平台边界

Android使用`remote_notifications`与`incoming_calls`渠道，通用安全内容之外再设private可见性；当前提醒默认无声音、无震动，不抢占已有声音。应用已加入插件要求的desugaring，沿用既有Lucide连接图标。iOS仅补系统通知delegate接线，权限与发布仍经共享插件。

Windows的共享依赖及初始化入口存在，但本地撤回要求打包身份，当前尚未验证，因此运行发布保持明确未支持状态。iOS/macOS权限、通知中心与点击也不能以Android结果代替；四宿主整包仍单独留证。选型依据及上游版本入口见[研究](../research/controller-notification-delivery.md)，实际运行结果见[验证记录](validation.md)。
