# 文件任务与快照所有权

应用 `app/lib/files/` 内的 `FileCatalog` 拥有远端浏览、筛选排序分页、搜索和图库快照；`FileMutationCoordinator` 拥有新增、重命名与删除批次；`TransferCoordinator` 拥有传输选择、冲突、取消、任务历史与恢复。应用会话直接组合三者，`FileCommands` 仅将应用命令字段映射到类型化调用。目录与传输事件同步进入同一应用事件序列，快照读取者只借用传输所有者的任务状态。`FileExecutor` 提供本机和被控设备的类型化元数据、复制进度和操作回执；`AppMediaCache` 通过 `FileCacheLeases` 提供本机缓存预算及路径租约，系统发布描述符由应用适配持有。文件字节留在原生层，资源归属见[架构](architecture.md)。

写入前收集选择项。每个文件依次使用未发布的临时文件、已刷新的 `finalizing` 记录与独立提交。提交回执丢失保留 `result_unknown`，不自动重放。取消等待在途执行结束，已发布文件和已完成的同批文件保留。移除历史不删除文件。

批次重启、移除及预算释放共享同一生命周期准入，在首次等待前登记；旧预算释放未确认时不能复用其租约。取消与关闭先撤销未完成的准备，再等待实际预算申请及交接结束。迟到预算由原准备对象精确释放，释放失败保留原责任供重试；不能在任务已移除或所有者关闭后重新写入排队任务。

新增目录、重命名与批量删除由 `FileMutationCoordinator` 在首次等待前登记。`AdbFileExecutor` 为整批固定一次精确设备连接，后续项目不能重新选择重连后的连接。设备停止及全局关闭撤销该批准入，等待在途创建、执行和实际句柄关闭；迟到句柄仍由原批次接管。关闭失败保留同一批次和句柄供重试，返回 `mutation_cleanup_unconfirmed`，阻止该设备的新变更；重试清理不重放已提交的操作。

媒体预览通过 `FileReadBatch` 一次固定实际连接，后续快照、复制、提交及清理不能改选重连后的连接。`MediaArtifactCoordinator` 保留读取批次、缓存 writer 和尚未交付的读租约；实际 worker 与暂存句柄全部释放后才解除写入保护、释放预算并放行同路径队列。关闭失败保留任务并报告失败；设备停止和全局关闭沿原任务重试，不按路径删除仍可能被写入的 part。发布后的读租约只在全部清理确认且请求仍有效时交给调用者。

便捷文件执行也须在原生创建前登记精确连接及会话，执行或关闭失败只交付一个最终错误，并保留执行与清理原因。取消关闭失败时可结束公开等待，但精确读取者和在途 next 仍随原会话保留；后续确认实际退出后才释放。`AdbFileExecutor.stopForConnection` 先同步撤销该连接的新执行，再排空迟到创建及原 worker，最后精确释放未发布 part；失败保留原登记，不能依赖错误调用方自行保存句柄，也不能关闭共享 services 代替精确回收。连接退休在首次等待前向目录、文件变更和传输所有者发起取消，同时撤销精确执行器准入；应用关闭同样并行发起三者关闭和执行器排空。目录所有者关闭不单独取消变更或传输，执行器回收也不能替代各所有者的日志与预算收尾。首个关闭失败应及时报告，承载连接仍保留供重试。

传输的清理责任独立于 worker Future 是否返回。清理未确认时持久保存 `cleanupPending` 和 `result_unknown`，保留缓存预算与原执行对象；取消、停止设备、关闭、重启任务和移除历史均不得越过该责任。清理成功只恢复已经确认的执行结果，提交回执未知仍为未知。冷重开时，只有执行器报告相同稳定 `fileScopeKey` 已成功换发另一 `fileScopeId`，且其 attach 契约确认前代操作与片段实际排空，才能解除清理标记；这不确认提交结果、不自动重放。同 id、其他 key、缺失事实或缺少原句柄均不作为回收证明。

`file_tasks.v2.journal` 是按序刷新的日志，压缩使用原子替换。旧 Rust 日志仅作只读迁移输入；序号、代次异常及不完整尾部拒绝推测恢复，持久化失败后停止接受写入。一个所有者对应一个私有目录；同 isolate 内仅对相同规范化目录和相同执行器实例保留附着交接的缓存租约，重启 isolate 或进程后重新核验。断电后的目录持久性未验证。

搜索和图库允许四个活动快照、十六个保留快照，受三十秒、五万条目、三十二层和每目录四千零九十六份事实限制。图库完成后冻结排序。排除子符号链接，仅允许显式存储别名作为根；无权、截断和观察到的变化仍作为部分结果。图库更窄的预算见[图库](gallery-index.md)。

外部分享导入与来源保留由同一应用 `ShareCoordinator` / `ShareStore` 提供，传输通过 `FilePublicationLeases` 直接调用该所有者；不经包内应用桥或 Rust 产品账本。只有完整持久任务引用可解除传输保留，格式与恢复边界见[内容交付](content-delivery.md#外部分享接收与传输来源)。分享提交在首次等待来源登记前，由传输所有者记录所属设备、取消状态和结算责任；设备停止与全局关闭等待来源登记及其后续发布收尾。登记迟到成功时，已取消请求只完成来源收尾，不创建新传输或借用后继连接。已持久发布的批次与真实回执保持原事实，来源登记失败仍保留原错误及来源所有者的未知保护。

验证入口及环境见[文件所有者验收](file-ownership-validation.md)。
