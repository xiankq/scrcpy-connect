# iOS Liquid Glass 逐页视觉审计

审计日期：2026-10-19。源稿：`designs/mobile.pen`。本文件记录初始发现与后续待办，最终修复和验收结果由主代理回填。

## 证据与范围

- 已通过 Pencil MCP Get 扫描全部 **94 个页面 Frame：92 个手机页、2 个大屏页**，检查页面结构、组件引用、可见状态、标题、填充、渐变及布局问题。
- 已截图抽看 **18 个设计页**：`lUDPa W3GRn MaHXL XPceX nqQEb w6WUAT sepTa lm0us a05tWj H0TFx OxyeM DtZbX FkCjb UwGyp TMxVJ ERONu RqDYL tbWkA`。其余页面只有结构扫描，不能记作逐页肉眼验收。
- 已查看已有 Flutter 截图中的设备列表、工作台、外观、设置四张；它们位于系统临时目录 `/tmp/connect-refined-ui/`，属于本轮修改前证据，不代表最终运行结果。
- 已静态扫描 `lib/pages` 下全部 **41 个 `*_page.dart`**。检查代码里的页面标题、主要容器及选择/动作组件，并对重点差异读取实现；未逐页运行全部业务状态。
- 本审计未执行真机业务、动态折射、手势、读屏和性能验收，也未因共享组件统一就将引用页面全部标记通过。

用户最新纠正：**“黑色的主题色不要改，我说的是点缀色。”黑白主题及黑色主动作保留**；亮色仅用于图标、连接状态、警告、危险等有明确语义的点缀。材质实施代理正在按此恢复主题；最终以 [design.md](../../designs/design.md) 为唯一规范来源。早期将黑色本身列为缺陷、建议全蓝主题的判断已撤回。规范变更不等于全部实例和实现已复验，本文不建立新的颜色、尺寸或光学参数表。

最新用户要求：**删除所有页头和普通列表项二级描述，保留状态正文**。设备/任务当前状态、错误与校验、进度、通知正文、原文件归属、来源目标核对属于实际内容；应按语义处理，不能批量删除全部小字。

## 统一规则与衍生验证

所有视觉值继续来源于 [design.md](../../designs/design.md) 和对应 Pencil implementation token，不在此文另建规范。

- 保留黑白主题和黑色主要动作；中性分组内容承载文件、通知、表单与设备信息。亮色仅用于语义明确的图标和状态点缀，不能将整个主题改蓝；正文不要用亮色降低可读性。
- 玻璃用于浮动导航、工具、菜单与sheet；不要给每个普通列表行加玻璃，也不要多层完整玻璃互叠。
- 标题与普通列表项删去二级描述后，统一单行导航语义和行节奏；实际状态与任务正文保留。
- 远端Android界面、照片和视频保持原内容外观；主控主题色与点缀色不污染远端内容。
- 降低透明度采用清晰实体材料；减少动态保留即时反馈；辅助变体不能因“更像玻璃”被覆盖。
