# 厂商互联功能与仍需补齐的产品流程

研究日期：2026-10-16。以厂商官网、开发文档与中国区 App Store 的开发者发布记录为依据；未安装或操作这些产品。厂商功能证明某种体验存在，不证明免 APK、普通权限的 ADB 产品可以原样实现。

**范围更新：** 用户本轮明确移除录屏、文件／相册自动备份，短信通过通知进入被控手机原应用。下方保留厂商事实及此前候选推论，旧的备份与自动回写建议不再作为当前需求；最新选择见[功能取舍](../../designs/prod/scope.md)与[页面路由专项调查](manufacturer-scope-xiaomi.md)。

| 来源 | 有证据的体验 | 本项目尚需明确的部分 |

OPPO 官网正文依赖 JavaScript，本轮可检索到其官方功能分类，但没有从该页面获得完整的编辑回写规则。编辑后保存至远端的体验以华为官方帮助为直接证据；第三方转载 OPPO 手册未作为确定依据。vivo 官网也注明机型及第三方应用适配限制，不能将宣传范围当作本项目验收结果。

## 3. 工程推论：完整互联还需要明确这些流程

以下保留早期从厂商体验推导的候选作为研究历史，不是当前执行清单。最新范围已否决备份、自动回写、专用相机和热点等扩张；只有本机手动取用、系统分享、原应用接续与通话目标继续。

- **跨设备编辑。** 远端文件交给主控本机编辑器后，需要知道哪份文件正在编辑、修改是否已保存、是否已写回、远端是否也变化。主控 Android 普通应用可以使用受控内容 URI，但第三方编辑器的写入方式和回调需要验证，不能承诺所有编辑器自动回写。平台文件边界见[运行时报告](flutter-rust-platform-runtime.md)。
- **相册取用与备份。** 实时相册反映被控设备当前内容，备份则是持久副本；需要独立展示授权、来源、已备份范围及失败项。增量识别不能只凭文件名，远端修改、重名、时间变化和 Live Photo／动态照片的组成也需要核查。
- **本机接续。** 用户可能希望把链接交给主控浏览器，而不是始终在远端窗口继续操作。通用内容分享、应用可识别的链接、应用合作传递的进度分别验证；不能从 ADB 权限推出任意应用的私有编辑状态可自动迁移。
- **系统分享与应用接收。** 厂商产品把入口接入系统分享面板和目标应用；本项目还需验证主控分享入口、目标内容落地、URI 授权以及远端应用能否接收。尤其图片／文件剪贴板不能退化成一条路径字符串，见[输入与剪贴板报告](mobile-input-and-clipboard.md)。
- **硬件共享与网络便利。** 相机、通话、热点等需要独立权限和链路；当前只保留通话专项，相机拍摄进入原应用，热点和通用硬件共享移出范围。厂商系统集成不等于 scrcpy 协议已有这些扩展，通话和麦克风区别见[媒体报告](scrcpy-media-and-server.md)。

## 4. 当前访谈前沿

Q35 之后用户明确将后续常规功能是否需要交给代理，要求依据已有厂商产品自行取舍；因此不再等待 Q36 单独作答。Q37 用户要求参照 scrcpy 最新版单应用启动能力，已再次核实 GitHub latest 指向 5.0.1：官方支持 `--list-apps`、`--start-app` 及与 `--new-display` 组合。应用互联主线据此采用远端真实应用窗口；链接等内容的本机打开作为独立便利动作，不将应用合作 SDK 定为产品基础条件。[最新发布](https://github.com/Genymobile/scrcpy/releases/tag/v5.0.1)、[指定应用启动](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/device.md#start-android-app)、[虚拟显示](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/virtual-display.md)

此前代理曾选择跨设备编辑回写、新照片快速取用和主动开启的本地备份。最新范围已移除备份及自动回写，只保留照片预览、手动取用和编辑后主动重新传回；不能把旧代理选择或当前选择写成用户逐项确认的原话。

主控增强调试路线已被 Q33 否决；这份报告不以增加主控调试或被控 APK 来补齐厂商体验。四端可编译与各平台运行能力分别验收，见[编译交付约束](cross-platform-build-contract.md)。

## 5. 本轮补充：跨端入口与原应用接续可以并存

OPPO 官网把文件管理、跨端交互和内容同步分别组织，其[通信共享隐私说明](https://connect.oppo.com/privacy/oshare.html)还列出接打电话、收发短信与接收通知。这证明厂商提供这些能力，不代表本项目要同时重建独立短信界面。[OPPO Connect](https://connect.oppo.com/zh-CN)

vivo 国际官网既描述手机镜像中的相册／文件拖拽，也提供直接访问手机文件夹的文件互传；任务接力可预览、复制和保存新照片／截图。两条路径支持本项目“原应用操作 + 专用内容取用”的组合，不需要追加自动备份。[vivo Office Kit](https://pc.vivoglobal.com/)

Phone Link 的官方通知指南说明，在支持的设备上可从通知进入手机应用交互；其平台和配套应用条件不能直接转化为本项目免安装被控端的实现保证。[通知指南](https://support.microsoft.com/en-au/windows/apps/view-and-manage-mobile-notifications-on-your-pc)、[平台与设置条件](https://support.microsoft.com/en-us/windows/apps/phonelink/phone-link-requirements-and-setup)

本轮 OPPO 首页和 vivo 国内官网正文仍依赖 JavaScript，相关分类依据官方搜索索引；vivo 详细操作依据可读取的国际官网。没有以二手文章补出确定流程。
