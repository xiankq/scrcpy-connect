# 通用能力包与应用内业务整合

`packages/` 仅保留 `design_system`、`adb`、`scrcpy` 与 `media_codec`，分别承载通用设计系统、ADB、scrcpy 和媒体解码能力。设备记录、授权身份选择、重连与后台策略、文件任务与恢复、产品偏好、活动归属及界面呈现均由 `app/` 整合。Rust 实现统一放在与能力包同名的 `rust/<package>/`。FRB、生成代码和加载细节由能力包内部维护，应用只使用公开 Dart 接口，不设置应用专用桥接包或 Rust 产品运行时。

ADB 与 scrcpy 的公开概念、参数及行为对应其上游协议和工具；产品设备标识、页面租约、后台策略与聚合 JSON 命令不进入这些通用接口。设计系统保留 token、主题、材质和通用控件，业务组件留在应用。应用 Dart 所有者完成逻辑窗口准入、打开任务的持久化及质量交接，再调用通用捕获执行；根据精确捕获句柄附着控制与媒体源，不重复创建捕获。媒体数据保持原生路径。

Dart 原生能力、成熟通用包，或容易实现且没有性能压力的逻辑优先在 Dart 完成。Rust 仅承载有明确协议、原生互操作或性能理由的机制；跨语言边界不因原有实现所在位置而保留。每个含 FRB 的能力包独立维护绑定；同一原生宿主需要共享连接时组合普通 Rust 库，只生成一个 FRB 入口，通过配套 Dart 能力持有同一连接，不跨动态库传递 Rust 内部对象。

此前按产品能力建立多个 Dart 包，增加了发布与依赖边界，却没有形成可脱离本应用使用的能力。将业务模块收回应用后，仍按状态所有者组织独立库和测试；需要跨平台协议实现的通用能力才承担独立包、原生实现和构建契约。代价是应用内模块更多，因此继续以实际依赖图核验方向与循环，而不借增加包数量表达模块化。

本决定收敛早期按产品能力拆包的边界，补充 [0007](0007-capability-packages-and-native-media.md) 的应用／通用能力归属，保留其原生媒体与固定依赖决定。原生绑定的具体组装位置由[当前实现职责](../implementation/architecture.md)维护；包的独立性不以复制连接或跨动态库传递 Rust 内部类型为代价。
