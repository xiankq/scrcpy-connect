# 按能力拆包与原生远控媒体

主控只需要实时远控媒体。移除 fvp/MDK 和本地媒体播放依赖；`media_codec` 直接导出 Flutter 组件，Rust scrcpy 入口把带代际的压缩包交给 Rust FFmpeg 解码核心，不再封装 MKV、建立 HTTP 中转或经过 Dart 视频字节事件。

FFmpeg 固定源码与构建配置，仅保留远控视频解码、必要解析和像素转换。AV1 软件回退使用独立裁剪 dav1d。平台硬解及 GPU 纹理互操作按宿主选择；硬解失败按当前 GOP 恢复软件解码，不把平台解码接口名称当作物理硬件加速证据。平台代码仅承担 Flutter 纹理、系统音频输出与必要系统接口；控制、状态和解码尽量由 Dart FFI 与 Rust 完成。

`flutter_adb` 独立提供 ADB 能力。移动端通过 Rust 访问 adbd，桌面固定打包官方 ADB。统一接口保留后端能力差异：无法保证的 TLS 或授权行为明确返回限制，不静默降低保证；shell 退出码、二进制数据、取消与所有权不能由成功提示文字推断。

产品策略、设置、连接编排、文件筛选与索引等不需要 Rust 热路径的业务归 Dart 能力包。`device_runtime` 只组装能力和管理应用生命周期；协议契约、日志、连接、文件、远控媒体各有独立模块与测试。迁移以状态所有者和执行职责为单位，删除被替代的业务实现，不长期维护两套产品状态。Rust 保留必要传输、scrcpy 协议、高吞吐执行与解码；安全条件在执行入口仍需核验。

选择此方案是为了同时控制媒体包体积、队列延迟和跨平台维护成本。代价是需要自行维护有限的平台纹理/音频胶水、解码回退和构建工具链。实际性能及完成状态由版本化验收记录承担，本决定不等同于所有平台已运行验证。
