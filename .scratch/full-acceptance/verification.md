# 邻接全功能验收记录

本轮从 [54 个路由入口](routes.md)、[产品规格](../../designs/prod/README.md) 和 Ardot 工作稿梳理覆盖范围。下面按实际操作和看到的结果记录。路由表保留待实跑状态，避免把代码入口、启动或自动化用例当成设备验收。

仓库门禁通过。Flutter 共 484 项测试通过，包含本轮增加的六项回归。Rust 暂存发布用例另行核对了同名文件保留、发布成功和发布后身份。Android 同签名覆盖验证与模拟器启动结果单独记录。

## 已核对的链路

| 链路 | 实际结果 |
| --- | --- |
| USB 和 TCP | ADB 最初在 USB 和独立 TCP 服务上都完成握手，核对为同一台小米 12。macOS 应用经 IP 方式连通并可重连。应用自己的 USB 检查在接口释放和冷启动后仍未发现设备。重新挂载及重启原 ADB 后，macOS 能看到 USB 硬件，ADB 暂未恢复枚举，TCP 仍正常。 |
| macOS 添加与输入 | 提交空地址可看到字段错误。修复后从端口提交，用键盘验证文字进入地址框。越界端口的焦点和拒绝提交由组件测试覆盖。 |
| 工作台与设备详情 | 工作台显示电量 100%、已充满，与 Android 电池系统读数一致。详情从加载占位切换为设备信息。 |
| macOS 整机远控 | 看到三个小球和渐变底色后收到真机画面。Escape 退出手机上的设置搜索。远控工具展开后可截图，返回原画面并可在窗口选择中返回工作台。 |
| 同设备双会话 | 从全部应用打开独立设置，收到首帧。保留它再打开整机，同一列表能切换两路。只关闭独立应用后整机仍在。修复并复验独立应用的「返回工作台」，实际回到该设备工作台并保留会话。 |
| 双设备并排 | macOS 同时打开小米 12 的显示设置和 Android 模拟器的声音设置。窗口列表关闭时，应用若暂时失去输入焦点，旧构建会让两路继续停在暂停。修复后重跑首次并排、退出并重新并排，两路都继续播放。点选任一边再按 Escape，只有对应设备退出设置。两侧的触控返回也分别核对了 Android 的前台页面。关闭小米会话后，模拟器仍能继续播放。 |
| 画面与控制 | 小米 12 的 60 FPS 改为 30 FPS，离开再进入仍为 30 FPS，随后恢复 60 FPS。清晰度弹层原先漏掉设备保存的 1280P。修复后在 macOS 真机链路确认 1280P 已显示并勾选，浅色和深色窄屏大字回归均通过。 |
| 取消系统分享 | 从真实截图预览打开系统分享，取消后暂存仍在，可直接再次打开。再取消仍可重试。已有接收方时需要核对的分支有自动化回归。 |
| 文件和搜索 | 在小米 12 下载目录用独立样本进入四层，返回后上一级仍显示目录。当前目录按完整样本名搜索得到唯一结果。 |
| 取回原件 | 原版已传完 32 字节，因宿主缺少安全发布而失败。新构建用同一文件取回，详情显示已完成，本机暂存与源文件 SHA-256 一致。测试另覆盖同名目标保留和回执丢失。 |
| 相册 | 首次检查达到时间上限。放入独立照片样本后，手动刷新保留旧列表，点「更新照片」后见到样本和日期分组。优化后在一次冷启动中约 6 秒见到样本，检查仍在继续。打开样本可切到原尺寸，再回到相册。也修复了新结果待采用时误显示无法读取的提示。 |
| Android 安装包 | 最新验收 APK 使用相同签名和与原包相同的版本号覆盖安装小米 12，包可启动，设备首屏可见。发布包内包含 Cupertino 图标字体。 |
| 设置与关于 | 实际打开后台运行、媒体暂存、设备记录与恢复、授权密钥、运行日志。关于页各行可见，无下划线。测试包的检查更新和更新记录均给出渠道不可用提示。许可证可打开，系统默认标题仍是英文。 |
| 传输总表 | 切换设备和传输标签，确认样本记录在总表中可查。 |

## 尚需补验

- 连接与资料。macOS 应用内 USB 连接、附近发现、扫码和配对码的实际授权、无回应和拒绝、变更传输方式、断网后的会话恢复、设备记录和密钥迁移。
- 远控。验证并排时的系统剪贴板隔离、原生窗口聚焦和关闭、移动端前后台和折叠、打开失败、声音、屏幕电源、旋转，以及清晰度和帧率的实际输出。
- 内容。文件批选、发送目录、冲突、中止、外部分享导入、目标系统保存、接收应用最终打开回执、视频，以及各异常状态的设计稿对照。
- 通知与电话。真实新通知、过期接续、清除、通话接续和系统权限。
- 设置。后台切换和保活、当前活动、导入导出、暂存清理、日志导出、主题与动态效果、成功更新渠道和无效路由。
- 视觉。首次空态、浅深色、大字、窄窗和折叠的设计对照需要逐平台记录。实际比对过的局部见上表。

| 需要的条件 | 为什么需要 | 验收动作 |
| --- | --- | --- |
| 小米 12 恢复 USB 枚举 | 用系统 ADB 和邻接自己的 USB 检查区分线材、接口和应用服务问题 | 重新插拔后先看 ADB 是否在线，再从邻接添加页走检查、授权和进入工作台 |
| 小米 12 和独立模拟器作为两个被控端 | 系统剪贴板需要验证焦点切换后只同步到选中的设备 | 两边分别打开可输入的测试页面，用不同的测试文字核对手机和宿主剪贴板 |
| 可操控的 iOS 模拟器界面或测试设备 | 当前主机的模拟器可由 `simctl` 启动取屏，未找到可操作的 Simulator 应用界面 | 在手机、平板和 Duo 上走添加设备、远控、文件交付及前后台恢复，并对照相应画板 |
| 测试通知、测试通话和已授权的被控端 | 接续、过期与清除要用真实状态区分 | 产生专用测试通知，分别在有效期内和失效后点开，记录手机是否进入正确页面。用测试通话核对接续和结束 |
| 配置了测试更新渠道的安装包 | 当前构建只能覆盖无法检查的状态 | 接入有已知新旧版本的更新源，依次验证无更新、有更新、下载入口和网络失败 |

## 复现入口

- 仓库门禁使用 `./scripts/check.sh`，包含生成一致性、架构、格式、Dart 分析、Rust 和 Flutter 测试。Android 调试包验证使用 `./scripts/check.sh --android`。
- 模拟器记录位于本机临时目录 `/tmp/interconnect-full-acceptance`。Android 的启动回执、进程、首屏和系统无响应分别核对。iOS 使用 `simctl` 启动、检查进程并截屏。个别启动截图只显示加载状态。
