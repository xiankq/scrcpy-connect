# 09 · 文件管理、部分成功、取消与恢复资格

Status: ready-for-agent
Type: research
Priority: P1
Depends on: 01, 14
Requirements: R28–R30、R38

## 问题

哪些文件操作和恢复语义能在远端路径、SAF与MediaStore端点之间可靠兑现？

## 研究输入与边界

一手依据与已有调查位于 `docs/research/`：flutter-rust-platform-runtime.md；adb-host-and-connectivity.md。入口见[需求审计](../requirements-audit.md)和[任务索引](README.md)。不把文档调查、编译与真机通过混为同一状态；现行规格与用户后续纠正优先于历史研究候选。

## 工作与交付物

- 覆盖目录/搜索/新建/重命名/删除、文件夹和批量、双向取回与本机打开；不给App私有目录虚构可访问权限。
- 记录endpoint可读/写/创建/覆盖/rename/seek/空间/grant能力，验证staging、校验、提交和取消残留，区分传完字节与真正完成。
- 处理同名三选项/当前任务应用、目录部分成功、源变化、软链接/循环、Unicode/大小写、空间满、授权撤销和路径转义。
- 给每种组合的可恢复条件与不支持原因；本机编辑仅主动传回，不建自动回写/备份/版本中心。

交付到对应研究报告及能力／流程矩阵；涉及代码或画布验证时保留版本、可复现步骤与证据。依赖项约束对应实验与最终结论，资料研究可先开始。临时截图与日志样本按隐私处理后放临时目录，不把设计预览纳入 Git。

## 完成条件

- [ ] 逐项任务详情能解释成功、失败、取消、待清理、不可恢复及结果未知；取消不把半成品标完整。
- [ ] 源/目标任一不支持恢复时不提供虚假恢复按钮；破坏性操作有明确对象和结果。
- [ ] 交付端点矩阵、故障记录与产品流程，沿用Q21不重复问冲突默认。
