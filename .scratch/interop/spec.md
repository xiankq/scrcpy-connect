# 跨设备互联产品规格

创建：2026-10-16；当前核查：2026-10-17。状态：已进入实现，Android整包和部分真实双机流程通过，完整产品与四端交付未完成。当前缺口以[完整重新核查](completion-reassessment.md)为准。

最新范围：用户已移除录屏、文件／相册备份；短信只提供通知入口，完整处理进入被控手机原应用。代理根据新授权进一步收敛其他页面，当前清单见[功能取舍](../../designs/prod/scope.md)。此前研究中的候选能力不自动构成产品承诺。

本规格汇总用户已确认的目标，以及 Q35 后用户授权代理参照厂商产品自行作出的常规功能取舍。功能范围按完整互联产品规划；实现中的先后依赖不代表删减功能。原始回答见[访谈记录](interview.md)，术语见[词表](../../GLOSSARY.md)，技术证据见[研究索引](../../docs/research/README.md)。

面向设计稿的产品定位、信息架构、用户流程与交互规则在 [designs/prod](../../designs/prod/README.md) 持续维护；本规格保留研究与授权背景、工程职责及验收边界。

全会话审计见[60项需求对照](requirements-audit.md)，版本和能力见[分级基线](compatibility-matrix.md)，后续研究与设计补齐见[20项任务](issues/README.md)。这些文件区分已有研究、代表稿与尚未执行的构建/真机/缺失状态，不把设计页数视为全流程验收；当前页面清单统一见[页面与转换](../../designs/prod/user-flows.md)。

## 1. 产品定位与约束

- 面向普通用户，手机控制手机优先，兼顾平板与未来桌面布局。设备列表是固定首屏，设备平等展示，不设置主力／备用角色；选择设备后进入其工作台。
- 被控设备为 Android，无 root、无额外 APK；通过系统 USB／无线调试授权，允许 ADB 推送并临时运行 scrcpy 或扩展 JAR。设置引导使用用户可理解的步骤，不要求输入命令。
- 主控始终不要求开启调试；主控侧权限通过普通应用的系统授权取得。
- Android 是当前功能实现与运行验证重点；Android、iOS、Windows、macOS 均须具有实际可编译的交付结果。编译通过、运行可用、特定功能支持分别记录。
- USB、局域网无线及已有 VPN／网关等路径提供的可达跨网 ADB 纳入范围。账号云服务、公共中继、自动穿透和厂商私有协议不作为基本使用条件。
- Rust 完整 ADB 主机库、Flutter、flutter_rust_bridge、Hooks／Riverpod 与 monorepo 为既定技术方向。ADB 依赖尽量纯 Rust，依赖选择必须同时满足目标平台与安全成熟度要求。

## 2. 功能范围与证据状态

“已有路径”表示上游存在功能或源码接口，均不代表本项目实测通过。“需扩展验证”保留产品目标，并要求在真正可用时启用对应操作。

| 功能域 | 产品行为 | 当前技术依据与验证状态 |
| --- | --- | --- |
| 连接与设备 | 发现、配对、手动地址、USB、网络切换、重连、设备状态与授权管理 | AOSP ADB 与 Rust 候选已有路径；完整协议、身份归并与平台权限需验证 |
| 屏幕与输入 | 直接触控、多点、导航键、键盘、旋转、全屏、低延迟预设、息屏控制 | scrcpy 已有路径；Flutter 媒体、中文输入与目标 ROM 需验证；不引入查看模式 |
| 应用互联 | 应用列表／搜索、最近与常用、指定应用启动、独立窗口、窗口尺寸适配、多窗口切换 | scrcpy 指定应用和虚拟显示已有路径；多任务、资源与单实例迁移需验证 |
| 声音与截图 | 设备级音源、单路默认、固定／混音、后台声音和就近截图；不做录屏 | scrcpy 已有路径；fvp/MDK 同步、旋转和生命周期需验证 |
| 文件协同 | 分类／目录浏览、搜索、基本文件管理、批量传输、文件夹、冲突、取消／恢复和本机打开 | ADB sync 与主控内容 API 有路径；权限、部分文件和断点恢复需验证；不建设自动回写或版本中心 |
| 相册 | 图片／视频浏览、新内容快速取用、手动保存与分享；不做自动备份 | 厂商已有体验；远端索引、格式组合、主控权限需验证 |
| 剪贴板与分享 | 文本、图片／文件流转；自动同步跟随当前设备且可固定，明确发送到其他设备 | scrcpy 文本有路径；图片／文件需内容落地和授权；主控后台读取受系统限制 |
| 通知与短信接续 | 当前有效通知、远端清除／打开、原通知已有的快捷回复和断线状态；短信正文与会话进入原应用 | 通知监听、动作及定位需验证；不建设短信数据服务、独立收件箱或长期通知档案 |
| 通话 | 来电与当前通话页面、接听／拒接／挂断和可用的主控声音；拨号／联系人／记录进入手机电话应用 | 电话控制和双向通话音频分别验收，音频涉及设备 HAL |
| 其他手机操作 | 拍摄、修图、应用管理及系统设置进入手机原应用；保留设备信息和连接诊断 | 不新增专用相机、虚拟摄像头／麦克风、热点管理、shell 终端或日志查看器 |

能力状态至少区分未知、需要设置、可用、受限和不可用。当前设备操作入口依据已探测状态呈现，设备详情保留支持条件与恢复方法；不把尚未验证的按钮画成已经可以成功执行。

被控 Android5+ 基础投控目标保留；启动原应用与需要较新系统的独立显示分别验收，媒体声音、同时本机发声及双向通话语音也不能共用一个版本门槛。主控最低版本另由正式依赖闭包确定，具体文档证据与实验缺口见分级基线。

## 3. 由代理确定的产品默认

这些默认依据用户既定方向及[厂商流程研究](../../docs/research/manufacturer-workflows.md)确定，可随实测结果修订，无需把每一项重新交给用户投票。

### 应用互联以远端真实应用窗口为主线

最新稳定 scrcpy 5.0.1 已提供指定应用启动与虚拟显示。主控以应用图标进入被控设备上的应用；移动端提供会话切换和系统允许的分屏，大屏呈现并排窗口，不把应用 SDK 合作定为基本使用前提。

以下只是官方能力示例，不是要求用户执行命令，也不表示 Flutter 会启动外部 adb／scrcpy 可执行文件：

```sh
scrcpy --list-apps
scrcpy --start-app=com.android.settings
scrcpy --new-display --start-app=com.android.settings --flex-display
```

实际由 Rust 编排 ADB、临时服务端、媒体与控制流。单实例应用接续真实任务，迁移时说明；目标不支持独立显示时允许在手机主屏打开。窗口关闭默认采用上游提供的保留内容并迁回主屏路径；强制停止进入被控手机系统设置，不建设独立应用管理面板。清理、异常断线和任务恢复需验证，不能由此保证应用自身永不结束。[官方指定应用说明](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/device.md#start-android-app)、[虚拟显示及关闭选项](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/virtual-display.md)

链接、文档等已取得的内容提供“在本机打开”便利动作。应用级进度接续按实际开放的链接／集成支持，不让它与真实远端窗口共用一个含糊的“应用迁移”语义。

### 文件与相册聚焦浏览、管理和手动取用

文档可在被控手机原应用中编辑，也可取回本机副本并交给本机应用；编辑本机副本后由用户主动重新发送，沿用普通传输冲突规则。不建设自动编辑回写、编辑副本跟踪或版本合并中心。

相册提供最近新增、预览、原文件手动取用与系统分享，不做文件或相册自动备份。文件同名沿用用户确认的询问、保留两份／替换／跳过和当前任务应用规则。

### 自动互联服从活动与授权边界

通知同步当前有效内容，不建设长期历史档案；远端动作重新核验，失败提供实际原因。短信及其他应用的完整阅读与编辑进入手机原应用，原通知已有快捷回复时仅提供就近动作。

补充源码调查已给出免 APK 通知 listener 的具体权限链，仍需设备验证。SMS 原生服务研究仅作能力资料，本轮产品不接入短信数据库或修改 SMS AppOps。双向通话音频与接听挂断分别验收，PSTN 依赖实际音频设备和厂商 HAL。[权限链报告](../../docs/research/android-shell-interop-capabilities.md)

剪贴板在用户开启后跟随当前操作设备，可固定对象；其他设备的复制不自动覆盖主控。主控具备读取资格时执行自动同步，提供系统分享和明确的复制／发送入口；后台普通应用读取受限时呈现真实状态，不要求开启主控调试。

后台维持连接、通知和传输，暂停不可见视频；主动开启的后台音频继续，通话按实际支持条件保持。瞬断恢复持续活动，主动停止保持停止；结果未知的发送、拨号和删除先核对，不能直接重放。已有重要通话和当前交互优先，新窗口和非焦点负载先降级。不创建录制或备份后台任务。

本轮补充的代理默认：主控锁屏不公开远端通知正文/验证码；新来电不自动抢占已有通话的麦克风与通信路由；已经提交的保存、分享或回复保留其原目标，界面焦点变化不改变该次操作。解锁/认证后重新核验原通知动作，失效则解释并交回手机当前画面。这些不是用户逐项确认，具体状态见产品流程覆盖表。

## 4. 技术边界与 monorepo

以下是职责划分，具体库版本在依赖闭包和互操作验证后锁定：

| 目录规划 | 职责 |
| --- | --- |
| `apps/connect/` | 一套 Flutter 应用与各平台 runner；设备、应用、文件、通知等功能界面 |
| `packages/design_system/` | 共享界面组件、主题适配与可访问语义；视觉值来源是 `designs/design.md` 与 Pencil implementation token |
| `packages/interop_bridge/` | Dart 侧 FRB 绑定与接口，不接管后台连接的真实生命周期 |
| `crates/adb/` | 可独立消费的 Rust ADB 主机库：协议、认证、配对、传输复用与设备服务 |
| `crates/interop_core/` | 设备／会话／能力模型、服务端编排、传输任务、恢复与资源调度 |
| `crates/interop_bridge/` | FRB 适配，导出稳定类型、操作与事件，链接各目标原生库 |
| `crates/platform_*/` | 按目标隔离 USB、发现、系统密钥与平台资源，不向共用接口泄漏原生句柄 |
| `servers/extensions/` | 必要的 Android shell JAR 扩展；与固定版本 scrcpy 服务端约定清晰的协议和生命周期 |
| `designs/`、`docs/` | 视觉规范、Pencil 画布、ADR、研究与验收依据 |

这些职责已在当前workspace部分实现；目录表仍描述职责边界，不表示每个规划目录均已创建。实际已使用`servers/companion/`和`servers/helpers/`；持续会话/恢复的所有权仍有偏差，详见重新核查A05/A22。Rust 核心拥有连接和持续任务，平台宿主负责后台执行资格、系统权限和句柄；Riverpod 提供界面状态投影，Hooks 管理界面订阅等局部生命周期。

scrcpy 服务端固定版本并验证协议匹配；优先保持官方能力边界，确需扩展时增加有版本协商的服务，避免多个进程各自争用设备剪贴板、音源和设置。fvp/MDK 保留可替换媒体接口，视频字节流、时间戳、同步、解码与 Surface 生命周期通过专项验证决定接法。

四端采用目标依赖、Rust cfg 和平台适配隔离。iOS 无通用 USB 后端不应影响 TCP／TLS 核心、FRB 与 Flutter app 构建；运行不支持的能力明确返回状态。具体依赖和验收见[编译交付约束](../../docs/research/cross-platform-build-contract.md)、[纯 Rust 依赖调查](../../docs/research/pure-rust-adb-dependencies.md)。

## 5. Pencil 设计范围

设备优先，使用 Lucide 图标、苹果液态玻璃风格及 Google DESIGN.md 规范。黑色是主题色，默认浅色，深色作为可选外观。功能图标和小元素允许紫罗兰、珊瑚、琥珀等彩色点缀；加强玻璃透色、亮边和悬浮层次，接听采用浅薄荷玻璃，避免深绿色实心按钮。玻璃用于导航、工具栏与控制浮层，文件、消息和其他内容维持清晰可读；具体视觉值只在已有目录规则指定的位置定义。

| 页面组 | 必须呈现的流程与状态 |
| --- | --- |
| 设备首页与添加 | 已连接／离线／需授权、发现、无线设置与配对、USB 授权、手动地址、失败恢复 |
| 设备工作台 | 手机控制、常用／最近应用、文件与相册、通知与通话入口、能力与后台状态 |
| 控制与应用窗口 | 直接操作、键盘、声音、截图、质量设置、旋转、会话切换、单实例说明和资源不足 |
| 文件与传输 | 分类／目录、基本管理、选择分享、任务详情、同名冲突、取消／失败／恢复 |
| 相册 | 新内容、预览、手动保存与分享、取用进度与失败 |
| 通知与通话 | 有效通知、轻操作／失效、进入原应用、来电与通话中；能力受限时说明 |
| 设备与应用设置 | 授权身份、功能支持、音源／剪贴板对象、后台开关与连接诊断 |
| 平板与桌面 | 设备导航与并排应用／文件、全局传输、多会话及主题关键布局 |

完整流程同时考虑空、加载、成功、失败和恢复，不只绘制成功首页。`.pen` 通过 Pencil MCP 或目录规则允许的 `pen interactive` 操作；规范先于具体画布值。当前为87个手机页面、2个大屏页面与共享组件板，移除退出范围的旧页，并补充相册多选、来电音频可用和降低透明度示例。移动端远控沉浸全屏，以可拖拽、吸附左右侧并收起的悬浮按钮退出；拖动不触发退出，收起保留可展开把手。整机、通知接续和独立应用统一采用此体验，退出保留其他活动。设计中的共用结构使用Pencil母组件与连接实例，全屏会话、退出状态、源画面与面板内容以组件组合表达；实例仅覆盖语义差异，修改母组件后核对正常与异常状态。每页为独立顶层 Frame，按设备、连接、远控、文件等十二类分行排列；见[用户流程与页面对应](../../designs/prod/user-flows.md)。页面覆盖关键流程与异常场景，未穷举每个状态组合。预览图片和 PDF 按需导出到系统临时目录，不纳入 Git。静态设计稿不等于运行验收。

## 6. 验收与技术未知

- **ADB：** 对照固定 AOSP 与官方 ADB 验证 AUTH、TLS、SPAKE2、发现、USB、复用、sync 双向压缩及相关设备服务；覆盖取消、坏帧和断线。
- **四端编译：** 核心、FRB 最终链接与 Flutter 整包分别通过对应宿主的实际构建，保留依赖图、工具链和产物；CPU／模拟器矩阵结合完整插件闭包确定。
- **Android 运行：** 模拟器覆盖界面和可模拟状态，真机覆盖 USB、硬解、触控／中文输入、后台、网络变化、热量、功耗和厂商差异。
- **媒体：** 测量输入到显示的延迟分布、音画同步、长时间静态、旋转、Surface 重建和多设备；玻璃与视频共同加载时一并测量。
- **内容：** 覆盖主控 URI 权限、远端文件权限、损坏／空间满／中断、源变化、同名冲突和图片／文件分享授权。
- **扩展：** 通知监听与动作、原应用接续、电话控制和通话音频分别记录系统／ROM 条件；用真实可执行结果更新能力矩阵。

技术未知继续由工程调查和 POC 收敛，不转化为一串让用户选择算法、证明能力或逐项批准功能的问题。目前已有Android构建、真实投控和部分内容协同结果，逐项证据见[验收记录](../../docs/implementation/validation.md)；未列通过的性能与兼容项仍须独立验收。

## 7. 审计后的研究与设计前沿

现有设计缺口以[32项流程覆盖](../../designs/prod/coverage.md)为准，本轮已补连接表单与设备管理、画质选项、视频、文件管理／部分失败、通知失效／未知结果、多设备对象与来电等代表稿；剩余重点为手机输入／横屏、通知认证、文件新建／搜索／实际结果、保存分享失败、通话路由和后台系统停止。继续按页面类型在同一源文件补变体，不为每一种错误机械增加页面。

研究任务覆盖完整ADB及无线对照、纯Rust与密码学、四端workspace/FRB构建、分级兼容、普通用户连接、JAR编排、fvp实时链、输入、文件、相册、通知、通话、音源/剪贴板/分享、后台、身份、玻璃/性能、竞品、许可维护和Android验收基准。每项有输入、依赖、产物与通过条件；创建任务不代表已执行。

## 8. Flutter代码组织与路由（2026-10-17追加）

用户最后明确采用浅层结构：`lib/pages/<页面>/<页面>_page.dart`。每个页面独立文件与目录，`pages`直接位于`lib`下；不加features/core/app分组。页面专属控件和状态就近放入该页目录，公共控件、服务和路由分别放`lib/widgets`、`lib/services`、`lib/router`，入口为根`main.dart`和`app.dart`。业务导航统一使用go_router，定义可识别的路径与实体ID；设备首屏、tab、全屏远控、系统分享、返回和替换均按实际路由管理。临时弹窗和系统选择器保持自身结果语义。路由重建不恢复已停止活动、不复制身份，不用必须存在的临时extra作为实体恢复的唯一数据源。

## 9. 工程化与平台职责（2026-10-17追加）

导航采用go_router_builder生成typed route与StatefulShellRoute；状态采用riverpod_generator生成Notifier及不可变state，build_runner统一生成。成员包继承根analysis_options，启用Flutter基础lint、严格类型与官方Riverpod analyzer plugin；CI必须实际检出违规、检查生成源过期，不能仅声明包名。生成文件与根锁文件入库，构建缓存不入库。工程证据见[导航实现](../../docs/implementation/flutter-navigation.md)和[工具链研究](../../docs/research/flutter-engineering-toolchain.md)。

Flutter/Rust为共享实现主体。Rust承担ADB、持续活动、导入/传输、容量/取消/恢复/持久化和媒体协议；Dart承担页面/共享交互编排、生成状态与跨端渲染组件。Android适配仅调用系统Intent/URI/FD、USB权限、前台服务、媒体焦点等实际OS能力并报告事实。原生层不独立复制任务、租约、重试和产品策略。已经实现的2176行Kotlin需逐块迁出共享职责；替换媒体路径必须保留真实PTS、渲染/输入尺寸、后台、焦点与重建验收，不能用删除Kotlin或搬成JNI冒称完成。
