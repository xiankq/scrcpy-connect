# 应用结构重构

## 已确认的方向

- 保留 core、pages、router；core 按能力聚合依赖、查询、状态和普通 Dart 实现。
- 页面可有专属 provider / Notifier，组合展示数据及编排页面流程；局部交互保留 Hooks。
- 页面目录按用户任务组织，不镜像完整 URL，不使用 index 层级或重复路径的长文件名。
- 纯数据、序列化与不可变状态归所属模块的 models/，生成文件跟随；接口、任务、取消令牌、资源句柄和有执行行为的对象留在实现处。
- App/Application 不混用。启动、生命周期、恢复、活动汇总和功能状态按实际职责命名，不保留全应用万能入口作为目标结构。
- 能力 provider 分别接收实现，不再从全应用能力容器取字段；应用作用域只连接事件、可见性与关闭。
- 启动只等待宿主接管和持久活动恢复等必要工作。功能实现按首次使用创建，读取空快照与关闭不得触发未使用资源的创建。
- 功能模块持有自己的子资源及可等待、可重试的关闭；应用启停只协调模块间依赖顺序。
- 保留连接代次、操作准入、取消、状态恢复水位与有序关闭的可观察保证。

## 实施与验证

1. 迁移页面与模型，修正所有 import、export、part 和生成物。
2. 拆出 application 职责，收敛命名与生命周期入口。
3. 按文件、设备、媒体、相册、设置等完整功能链迁移：暴露可独立替换的能力与事件入口，页面就近消费，去除全应用控制器参数、重复查询状态和能力转发。启动装配保留共享资源所有权，功能查询不接管应用关闭。
4. 核对 typed routes 的 URL、返回、恢复及资源身份；验证功能 provider 独立替换、旧回执失效、取消与清理。
5. 更新受影响的应用约束和架构检查，运行生成、静态分析、应用测试与架构门禁。

结构调整不改变视觉、产品入口、URL 和原生协议。

## 整体验收

- 启动装配不使用尚未赋值的 `owner!` 或访问生命周期 getter 来解除构造循环；模块借用明确能力，应用级启停不触及模块内部子资源。
- 所有按需资源只在功能使用时创建；空查询、取消、连接退休与应用退出不创建未使用的执行对象。关闭失败保留原对象，可等待并重试，宿主最后释放。
- 系统文档、USB、后台保持与音频的平台适配各归其功能所有者；共享平台通道只负责传输及协议适配。
- 连接、配对、USB 等复杂页面流程由页面专属状态所有者管理；表单控件、导航、弹窗及视图租约仍由页面持有。取消、换源、离页及迟到回执具有明确归属。
- 应用内部事件和恢复快照使用所属模块的类型；JSON 保留在平台、伴生协议及持久化适配处，业务消费方不自行拼接协议字段。
- 核对全部能力及页面的状态来源、命名、模型归属和跨模块依赖；不以文件拆分或新增转发层代替职责收敛。
- 验证实际装配链的按需创建、启动失败回收、关闭顺序与重试，以及页面流程、事件水位、路由和原生交付。替身入口测试与单次启动日志不能单独证明整体完成。
