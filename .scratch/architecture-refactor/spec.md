# Flutter 与 Rust 全面重构

## 目标与保持的行为

以实际职责、状态所有者和可验证接口组织应用，消除循环依赖、跨包私有访问、全局锁内远端等待、无关事件查询放大及迟到回执越权。手写代码注释使用中文，生成器标记、许可证、标准工具指令及原样来源保留。已有产品行为、视觉、授权身份与不可重放约束继续由原责任规格维护。

## 包与业务归属

最终仅保留 `design_system`、`adb`、`scrcpy`、`media_codec` 四个通用包。Rust 实现统一放在与能力包同名的顶层 `rust/<package>/`；FRB 配置位于仓库顶层，绑定和生成代码由各能力包内部维护。`app/` 不含 FRB 或 Rust，只调用公开 Dart 接口；产品策略、持久状态、文件任务和业务组合全归应用。`packages/` 与 `rust/` 只提供通用能力，不增加应用桥或包装产品 Runtime。容易用 Dart、成熟包实现且没有性能压力的能力留在 Dart。设计系统保留 token、主题、材质和通用控件。决定与理由归 [ADR 0008](../../docs/adr/0008-reusable-packages-and-application-composition.md)。

## 循环顺序

1. 建立静态分析与现有测试基线，并行只读审计应用、能力包和 Rust。
2. 为发现的实际失败建立精准回归，按资源所有权实施第一批重构。
3. 检查拆分后的依赖与生命周期，修复整合回归，继续收敛远控、ADB 与文件执行责任。
4. 核对中文注释及受控产物生成链，运行主机门禁与可用宿主运行检查。
5. 再审计最终差异，记录已解决问题、验证层级及仍需真实设备的证据。

## 已确认的审计范围

| 领域 | 有证据的问题 | 负责实现 |
| --- | --- | --- |
| Flutter 应用 | 控制器与状态/配置循环导入；音源所有权混杂；页面用全局事件计数重复读取；剪贴板遗漏连接身份；远控与根界面持有业务编排 | `app/lib/` |
| 应用业务模块 | 运行时同时拥有媒体、平台与分发；日志 `part` 依赖整个文件模块；多包源文件反向导入公共 barrel；清理异常阻断其他资源；重置设置不应用后台策略 | `app/lib/` |
| 执行与资源所有权 | 尺寸 shell 持状态读锁；停止在活动 registry 内等待；重新附着忽略私有目录；官方 ADB 在全局锁内启动；文件操作释放依赖隐含调用顺序；错误分类丢失 | 应用编排归 `app/lib/`，通用执行归同名 `rust/<package>/` |
| 原生媒体 | 单文件同时暴露包存储、容量、GOP、解码后端和像素转换；FFI 指针与线程所有权缺少安全文档 | `rust/media_codec/` |
| 防回退 | 缺少执行中的能力分层、私有接口与依赖环检查 | `tool/check_architecture.dart` |

验证结果归版本化[重构记录](../../docs/implementation/architecture-refactor-validation.md)，现行职责归[架构](../../docs/implementation/architecture.md)。本规格不替代产品、视觉或架构责任文档。
