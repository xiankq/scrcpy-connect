# 跨平台大屏、折叠屏与多窗口适配研究

核实日期：2026-11-14。资料只取 Android Developers、Apple Developer、Huawei Developer、Flutter 官方文档或官方视频。文中的“设计结论”是把平台规则转成产品约束的推导，均在结论旁附原始资料链接。

## 可以直接落成设计约束的结论

1. **布局依据必须是当前应用窗口，而不是设备型号或物理屏幕。** Android 用 compact/medium/expanded `WindowSizeClass`，Apple 用水平/垂直 size class，HarmonyOS 用窗口宽度断点；同一设备在分屏、自由窗口、折叠或外接显示器时都可能有不同窗口。([Android window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#window-size-classes)、[Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout.md)、[HarmonyOS 响应式布局](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-v5/responsive-layout-V5/))
2. **把可变环境建模成应用级 `WindowEnvironment`，至少包含窗口边界、方向、系统安全区、显示特征（折痕/铰链/挖孔）、姿态、窗口模式、输入能力和窗口/场景身份。** 这是对 Android `WindowInfoTracker`/`FoldingFeature`、Apple scene geometry/reserved region、HarmonyOS `WindowStage`/`WindowStatusType` 与 Flutter `MediaQuery`/`DisplayFeature` 的共同抽象，避免业务状态直接读取某个平台单例。([Android WindowInfoTracker](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#posture)、[FoldingFeature](https://developer.android.com/reference/androidx/window/layout/FoldingFeature)、[Apple Scenes](https://developer.apple.com/documentation/uikit/scenes)、[iPhone Duo reserved regions](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo.md#Reserved-regions)、[HarmonyOS 窗口生命周期](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/window-lifecycle/)、[Flutter MediaQuery displayFeatures](https://api.flutter.dev/flutter/widgets/MediaQueryData/displayFeatures.html))
3. **响应式布局应同时有“连续适配”和“断点换结构”两层。** 在窗口小幅变化时使用弹性尺寸、约束、伸缩、折行；跨越断点时切换单栏/双栏、底部导航/侧边栏、列表/详情。HarmonyOS 明确区分自适应布局（连续变化）和响应式布局（断点、媒体查询、栅格）；Android 和 Flutter 也要求按窗口大小切换 pane/导航。([HarmonyOS 布局简介](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V13/layout-intro-V13/)、[Android adaptive panes](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#content-panes)、[Flutter responsive/adaptive](https://docs.flutter.dev/ui/adaptive-responsive))
4. **折痕、铰链、挖孔和相机区域都是可用空间约束，不应放置关键文字或细触控目标。** Android `FoldingFeature` 暴露 bounds、occlusion 和 separating；Apple iPhone Duo 将铰链、内外摄像头定义为 reserved regions；HarmonyOS 要求悬停态避让折痕；Flutter 的 `DisplayFeatureSubScreen` 可将内容放到不被显示特征分割的子屏。([Android FoldingFeature occlusion](https://developer.android.com/reference/androidx/window/layout/FoldingFeature.OcclusionType)、[Android display cutouts](https://developer.android.com/develop/ui/views/layout/display-cutout)、[Apple iPhone Duo reserved regions](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo.md#Reserved-regions)、[HarmonyOS 折叠屏指南](https://developer.huawei.com/consumer/cn/doc/best-practices-V14/bpta-foldable-guide-V14/)、[Flutter DisplayFeatureSubScreen](https://api.flutter.dev/flutter/widgets/DisplayFeatureSubScreen-class.html))
5. **姿态变化应保持控制会话、选择和导航连续；布局可变，功能语义不能随空间消失。** Android 将折叠姿态和窗口变化列为 configuration change，要求用 `onSaveInstanceState`/`ViewModel` 保持状态；Apple 要求 iPhone Duo 在内外屏、各种 pose 保持相同功能和状态，并避免剧烈重排；HarmonyOS 折叠指南要求开合连续。([Android configuration continuity](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#configuration-and-continuity)、[Apple iPhone Duo best practices](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo.md#Best-practices)、[HarmonyOS 折叠屏应用指南](https://developer.huawei.com/consumer/cn/doc/best-practices-V14/bpta-foldable-guide-V14/))
6. **默认不锁定方向；若产品确需锁定，必须验证折叠展开后的窗口和 letterbox。** Android/Flutter 官方均提示方向锁会在折叠展开时造成兼容模式或 letterbox；Apple iPhone Duo 仍会在开合时调整大小。([Flutter large screens/foldables](https://docs.flutter.dev/ui/adaptive-responsive/large-screens#foldables)、[Flutter adaptive best practices](https://docs.flutter.dev/ui/adaptive-responsive/best-practices)、[Apple iPhone Duo Tech Talk](https://developer.apple.com/videos/play/tech-talks/111461/))
7. **多窗口必须由窗口/场景生命周期持有者管理，页面只订阅窗口投影。** Android Activity/WindowManager、Apple `UIScene`、HarmonyOS `UIAbility → WindowStage → MainWindow` 都允许窗口几何和生命周期独立于页面；Flutter 的单例 `window` 已弃用，代码应经 `View.of`/`PlatformDispatcher` 取得具体 view。([Android multi-window](https://developer.android.com/develop/adaptive-apps/guides/support-multi-window-mode)、[Apple Scenes](https://developer.apple.com/documentation/uikit/scenes)、[HarmonyOS WindowStage](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/window-lifecycle/)、[Flutter window singleton migration](https://docs.flutter.dev/release/breaking-changes/window-singleton))
8. **Apple 的 Liquid Glass 只作为控制与导航的功能层，不能把它当作跨平台内容背景 token。** HIG 要求 Liquid Glass 用于 tab bar、sidebar 等功能元素，内容层使用标准 materials；`regular` 用于文字较多或背景复杂的控件，`clear` 仅适合视觉丰富背景并需评估对比度。([Apple Materials HIG](https://developer.apple.com/design/human-interface-guidelines/materials.md)、[Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass))
9. **跨平台设计系统应把“语义层”（内容、控制、导航、系统避让）与“材质层”（Liquid Glass、Android/HarmonyOS material）分开。** Apple 系统组件会自动获得 Liquid Glass；Android/HarmonyOS 有各自系统栏、窗口标题栏和分屏分界线，直接复制 Apple 材质会破坏层级和可读性。([Apple Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/liquid-glass)、[Android window insets](https://developer.android.com/develop/ui/compose/system/insets)、[HarmonyOS 窗口模式](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/window-mode-overview/))
10. **所有关键操作都必须可在窄窗口完成，并为宽窗口提供额外 pane，而不是改变操作含义。** Android expanded 可显示 list-detail 双 pane；Apple HIG 要求 size class 改变时保持功能，仅改变可见功能数量；HarmonyOS 断点可切换一栏、两栏、三栏。([Android content panes](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#content-panes)、[Apple Layout size classes](https://developer.apple.com/design/human-interface-guidelines/layout.md#Size-classes)、[HarmonyOS 响应式组件](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-component-layout/))

## 平台事实与实现边界

### Android：大屏、折叠、WindowManager 和多窗口

- Android 把 adaptive app 定义为随应用窗口尺寸、折叠姿态、密度和字体变化而改变布局；在多窗口中窗口可任意调整，不能只按设备屏幕做判断。官方建议使用窗口尺寸类、Compose Material 3 Adaptive、非触控输入和全设备测试。([Get started with adaptive apps](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps))
- `WindowSizeClass` 按窗口宽/高分类为 compact、medium、expanded；expanded 可以同时显示相关 pane，compact/medium 通常显示单 pane。([Window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#window-size-classes)、[Content panes](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#content-panes))
- Jetpack WindowManager 的 `WindowInfoTracker` 提供 `DisplayFeature`；`FoldingFeature` 提供 bounds、orientation、state、`occlusionType` 和 `isSeparating`。完全遮挡（`FULL`）区域应完全避开，连续折痕（`NONE`）可作为分栏指导线；非平坦折叠屏可视为 separating。([WindowInfoTracker](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#posture)、[FoldingFeature API](https://developer.android.com/reference/androidx/window/layout/FoldingFeature)、[OcclusionType](https://developer.android.com/reference/androidx/window/layout/FoldingFeature.OcclusionType))
- 官方姿态指南覆盖 folded、flat、tabletop、book；双 pane 设计要给铰链留更宽 gutter，必要时把控件和文字放在铰链两侧。([Postures and orientation](https://developer.android.com/design/ui/mobile/guides/layout-and-content/postures-and-orientation))
- Android 7.0 引入 split-screen/PiP，Android 12 将多窗口作为标准行为；在 medium/expanded 大屏上所有应用都进入多窗口，Android 16（API 36）在 smallest width ≥600dp 的大屏上忽略方向、宽高比和 resizability 限制（厂商仍可有差异）。([Support multi-window mode](https://developer.android.com/develop/adaptive-apps/guides/support-multi-window-mode))
- Android 15/API 35 目标应用默认 edge-to-edge；显示挖孔区域必须使用 `WindowInsets`/`DisplayCutout` 的安全 inset 和 bounds，不能硬编码状态栏高度。([Display cutouts](https://developer.android.com/develop/ui/views/layout/display-cutout)、[Window insets](https://developer.android.com/develop/ui/views/layout/insets))
- **可执行约束：** Android 宿主应把 WindowManager 事件转成 `WindowEnvironment`；内容 pane 以窗口 bounds 减去 system bars/display cutout/hinge 后布局；在 `FULL` 或 separating 特征上禁止交互控件跨越；状态恢复必须独立于 Activity 重建。

### Apple：iPhone Duo、iPadOS/macOS scene/window 与 Liquid Glass

- iPhone Duo 是双显示、中心铰链、内外屏和多种 pose 的 iPhone；官方建议使用 size classes（外屏 compact、内屏 regular 的基本模型），不要为每个 pose 写一套布局。([Designing for iPhone Duo](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo.md#Device-poses))
- iPhone Duo 将外/内前摄和折叠区域定义为 reserved regions；标准 alerts、sheets、split views 会自动避让，定制视图可用 SwiftUI `ReservedRegion`/UIKit `UIView.ReservedRegion`。折叠时优先微调，避免控件突然消失；网格优先偶数列，使内容清晰分到铰链两侧。([Reserved regions](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo.md#Reserved-regions))
- iPhone Duo 外屏把 toolbar/tab bar/navigation controls 置于侧边，内屏横屏保持同侧；在 Split View 中左右 app 的 controls 位于各自外侧。产品不可把顶部/底部位置写死为跨 pose 的固定规则。([Vertical controls](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo.md#Vertical-controls)、[Prepare your app for iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111461/))
- iPadOS 窗口当前有全屏和 windowed 两种呈现；windowed 可自由调整大小、同时显示多个 app 窗口，并记住窗口尺寸和位置。窗口控制位于 toolbar leading edge，应用 toolbar 必须为它留空间。([Apple Windows HIG](https://developer.apple.com/design/human-interface-guidelines/windows.md))
- macOS 支持移动、调整、最小化、全屏和多显示器窗口；窗口有 main、key、inactive 状态，系统用外观区分哪个窗口接收输入。关键操作不要放在窗口底部，因为窗口可能被移出屏幕；应使用菜单栏、键盘快捷键和指针输入。([Apple Windows HIG](https://developer.apple.com/design/human-interface-guidelines/windows.md)、[Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos))
- UIKit scene 是一个 UI 实例的窗口和 view-controller 容器；多个 scene 可同时运行并共享进程，`UIWindowScene` 管理该实例的窗口和生命周期。通过 `UIApplicationSupportsMultipleScenes` 允许多个 scene；几何变化由 scene API 观察。([Scenes](https://developer.apple.com/documentation/uikit/scenes)、[UIWindowScene](https://developer.apple.com/documentation/uikit/uiwindowscene)、[Multitasking on iPad, Mac, and Apple Vision Pro](https://developer.apple.com/documentation/uikit/multitasking-on-ipad-mac-and-apple-vision-pro))
- Apple HIG 要求布局随 size class、方向、窗口、外接显示器、Dynamic Type 和安全区适配；size class 应反映可用空间，不能按设备类型或方向推断。([Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout.md))
- Liquid Glass 是跨 Apple 平台的动态材质，作为控件和导航的独立功能层；不要用于内容层，`regular` 适合复杂背景/较多文字，`clear` 适合视觉丰富的媒体背景并需处理亮背景对比度。([Materials](https://developer.apple.com/design/human-interface-guidelines/materials.md)、[Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass)、[WWDC25 Elevate the design of your iPad app](https://developer.apple.com/videos/play/wwdc2025/208/))
- **可执行约束：** Apple 宿主应以 scene/window 为状态边界；Flutter/业务层只消费该 scene 的 bounds、traits、safeAreaInsets 和 reserved regions。iPhone Duo、iPadOS、macOS 共享“可调整窗口 + 保持状态”的约束，但控制栏位置、窗口状态外观和菜单/键盘规则分别由平台组件提供。

### HarmonyOS ArkUI：自适应、折叠、分屏与自由窗口

- ArkUI 明确区分：自适应布局根据容器相对关系连续变化（拉伸、均分、占比、缩放、延伸、隐藏、折行）；响应式布局根据断点、媒体查询、栅格和窗口方向切换结构。窗口从 400vp 变到 1000vp 时，只有自适应布局会造成图片过大或留白，需增加断点换结构。([布局简介](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V13/layout-intro-V13/)、[响应式布局](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-v5/responsive-layout-V5/))
- HarmonyOS 应用窗口模式包括全屏、分屏、自由悬浮/自由多窗；分屏当前为二分屏，分界线可拖拽；自由窗口可移动、缩放并与其他窗口叠放，窗口尺寸由系统决定时不受 `WindowLimits` 约束。([窗口模式简介](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/window-mode-overview/)、[多设备窗口模式最佳实践](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-window-mode/))
- `module.json5` 的 `supportWindowMode` 可声明 `fullscreen`/`split`/`floating`；手机、折叠屏与平板支持矩阵不同，折叠屏展开态还可能进入左右或上下分屏。([多窗口支持](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/multi-window-support/)、[窗口模式矩阵](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-window-mode/))
- Stage 模型中 UIAbility 对应 WindowStage，WindowStage 管理一个应用主窗；辅助窗口由应用自行管理。窗口模式和可见性变化应由窗口事件监听驱动，而不是假定页面生命周期等于窗口生命周期。([窗口生命周期](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/window-lifecycle/))
- 折叠屏指南要求展开态/平板横竖屏适配、悬停态折痕避让、竖向/横向悬浮窗、上下/左右分屏，以及自由窗口尺寸变化；折叠开合过程中不能出现截断、错位、闪屏或交互中止。([折叠屏开发指南](https://developer.huawei.com/consumer/cn/doc/best-practices-V14/bpta-foldable-guide-V14/)、[智慧多窗布局适配](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V14/multi-window-layout-adapt-V14/))
- ArkUI `FoldSplitContainer`/`HoverModeStatus` 提供折叠状态、悬停状态、旋转角度和窗口状态（全屏/分屏/自由窗口）的组合信息，可直接作为 `WindowEnvironment` 的 HarmonyOS 适配源。([FoldSplitContainer API](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ohos-arkui-advanced-foldsplitcontainer/))
- **可执行约束：** ArkUI 页面先用连续约束保证任意窗口尺寸可用，再用断点切换导航/多栏；窗口适配代码监听 window/fold/visibility 事件，不能在页面首次构建时缓存屏幕宽高；主窗和辅助窗的资源/状态所有权分开。

### Flutter：官方能力与边界

- Flutter 官方把 adaptive 定义为“选择在空间中可用的布局和输入方式”，responsive 定义为“把 UI 放进可用空间”；大屏包含 Android 平板/折叠屏/ChromeOS、web、desktop 和 iPad。([Adaptive and responsive design](https://docs.flutter.dev/ui/adaptive-responsive)、[Large screen devices](https://docs.flutter.dev/ui/adaptive-responsive/large-screens))
- 大屏布局应按 `MediaQuery` 的应用窗口尺寸，而不是物理设备尺寸；官方示例建议按窗口宽度决定 Grid 列数，避免把“平板”硬编码成固定列数。([Flutter large screens](https://docs.flutter.dev/ui/adaptive-responsive/large-screens#layout-with-gridview))
- `MediaQueryData.displayFeatures` 当前只在 Android 填充；`hinge`/`cutout` 会阻塞显示，`fold` 表示折痕，折叠特征有 posture state；`DisplayFeatureSubScreen` 可避开把屏幕分成子屏的特征。([MediaQueryData.displayFeatures](https://api.flutter.dev/flutter/widgets/MediaQueryData/displayFeatures.html)、[DisplayFeatureSubScreen](https://api.flutter.dev/flutter/widgets/DisplayFeatureSubScreen-class.html))
- Flutter 官方正在为多 view/多 window 演进：全局 `window` 已弃用，推荐 `View.of(context)`/`PlatformDispatcher.views`；add-to-app 的 multi-engine 支持 Android/iOS/macOS，web 的 multi-view 是多个 `FlutterView`，这些并不等于 Flutter 应用跨平台创建原生独立窗口。([window singleton migration](https://docs.flutter.dev/release/breaking-changes/window-singleton)、[Add-to-app](https://docs.flutter.dev/add-to-app)、[Multiple Flutter screens or views](https://docs.flutter.dev/add-to-app/multiple-flutters)、[Flutter web multi-view](https://docs.flutter.dev/platform-integration/web/embedding-flutter-web))
- **能力不足的明确结论：** Flutter 官方文档没有提供一个稳定、统一的 Dart API 来创建/管理 Android Activity、iPadOS/macOS scene、HarmonyOS WindowStage 或桌面原生窗口；需要由各平台宿主/插件创建窗口，并把窗口环境和生命周期通过公开能力接口传入。官方资料只保证上述 `FlutterView`/multi-engine/multi-view 边界，不能把第三方 `desktop_multi_window` 等插件当作 Flutter 官方能力。
- **可执行约束：** 业务层使用 `MediaQuery`/`View.of` 的当前 view；Android 折叠特征由 Android adapter 提供，Apple reserved regions/scene geometry 和 HarmonyOS fold/window 状态由宿主 adapter 提供；任何跨 view 的状态同步都必须显式通过能力接口，不读取全局 window singleton。

## 平台差异对照

| 维度 | Android | Apple（iPhone Duo/iPadOS/macOS） | HarmonyOS | Flutter 统一层影响 |
| --- | --- | --- | --- | --- |
| 主要布局信号 | 窗口 size class + WindowManager DisplayFeature | iOS/iPadOS size class、macOS window geometry、iPhone Duo reserved region | vp 窗口宽度断点 + fold/hover/window status | 使用 `WindowEnvironment`，不得使用设备类型判断 |
| 折叠模型 | `FoldingFeature` state/occlusion/separating | iPhone Duo folding region/reserved region，标准组件自动避让 | `FoldStatus`、`isHoverMode`、`FoldSplitContainer` | 将 display feature 与 posture 分开存储 |
| 多窗口 | split/PiP/freeform；大屏默认允许多窗口 | scene 可并发；iPadOS 可调整窗口；macOS 多 window/key state | full/split/floating/freeform；WindowStage 管理主窗 | 窗口生命周期不等于页面生命周期 |
| 系统避让 | WindowInsets、DisplayCutout、system bars | safe area、窗口控件、Dynamic Island、reserved regions | 状态栏/导航条/折痕/窗口标题栏 | 所有交互控件依赖动态 inset |
| 材质 | Android system bars/Material | Liquid Glass 功能层 + standard materials | ArkUI/HarmonyOS system components | 只共享语义 token，不跨平台复制材质 |
| 官方 Flutter 入口 | Android `MediaQuery.displayFeatures` 可见 | 无 Flutter 原生 reserved-region API | 无 Flutter 原生 fold/window API | 通过宿主 adapter 注入平台能力 |

## 风险与需要在规格中声明的假设

- **坐标空间风险：** Flutter `DisplayFeature.bounds`、Android `FoldingFeature.bounds`、Apple scene bounds 都是窗口相关坐标；不能用物理屏幕坐标绘制控制条。([Flutter display features](https://api.flutter.dev/flutter/widgets/MediaQueryData/displayFeatures.html)、[Android FoldingFeature](https://developer.android.com/reference/androidx/window/layout/FoldingFeature)、[Apple UIWindowScene](https://developer.apple.com/documentation/uikit/uiwindowscene))
- **edge-to-edge 演进风险：** Android 15/API 35 目标应用默认绘制到 system bars/cutout 下方；旧版默认行为不同，必须以运行时 WindowInsets 为准。([Android window insets](https://developer.android.com/develop/ui/views/layout/insets)、[Android display cutout](https://developer.android.com/develop/ui/views/layout/display-cutout))
- **窗口模式矩阵风险：** HarmonyOS 多窗口能力随设备类型/系统版本变化，文档明确手机、双折叠、三折叠、平板、电脑支持矩阵不同；不能仅以 API 版本推断能力。([HarmonyOS multi-device window mode](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-window-mode/))
- **Apple API 代际风险：** iPhone Duo 的 reserved-region/arrangement API 是 iOS 26 及新 SDK 的能力；在较旧系统运行时必须回退到 safe area、size class 和标准组件。([Designing for iPhone Duo](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo.md)、[Prepare your app for iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111461/))
- **Flutter 能力风险：** Flutter 官方文档描述的是 view 和嵌入能力，而不是跨平台原生窗口管理；多窗口产品需求必须列入 Android/iOS/macOS/HarmonyOS 宿主开发和插件维护成本。([Flutter add-to-app](https://docs.flutter.dev/add-to-app)、[Flutter window singleton](https://docs.flutter.dev/release/breaking-changes/window-singleton))
- **状态连续性风险：** 折叠、旋转、分屏、自由缩放、scene 重建会触发配置/几何变化；如果控制会话状态只存在页面树，可能丢失当前操作设备、选中项或输入。应在会话/窗口所有者中保存并恢复。([Android continuity](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps#configuration-and-continuity)、[Apple multitasking](https://developer.apple.com/documentation/uikit/multitasking-on-ipad-mac-and-apple-vision-pro)、[HarmonyOS lifecycle](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/window-lifecycle/))

| HarmonyOS 手机/折叠屏 | 折叠/展开、hover、竖向悬浮、上下分屏、挖孔/系统栏、开合连续 | 折痕区域避让；断点切换不出现拉伸/截断/闪屏；弹窗可关闭且不被分屏边界遮挡。([Foldable guide](https://developer.huawei.com/consumer/cn/doc/best-practices-V14/bpta-foldable-guide-V14/)、[Multi-window layout](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V14/multi-window-layout-adapt-V14/)) |
| HarmonyOS 平板/2-in-1/电脑 | 左右/上下分屏、自由窗口移动/缩放、多窗口叠放、窗口可见性和生命周期 | `WindowStage`/窗口事件正确驱动状态；窗口缩放时连续布局，超过断点时结构切换；辅助窗不抢主窗所有权。([Window mode](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/window-mode-overview/)、[Window lifecycle](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/window-lifecycle/)) |
| Flutter widget 层 | 任意窗口宽高、文字缩放、Android `DisplayFeature` hinge/fold/cutout、无 display feature | `MediaQuery`/`View.of` 取当前 view；pane/安全区纯 Dart 测试覆盖；不依赖全局 `window`。([Flutter display features](https://api.flutter.dev/flutter/widgets/MediaQueryData/displayFeatures.html)、[window migration](https://docs.flutter.dev/release/breaking-changes/window-singleton)) |
| Flutter 宿主集成 | Android Activity/WindowManager、iOS/iPadOS scene、macOS window、HarmonyOS WindowStage 各自创建/销毁/恢复窗口 | 平台 adapter 提供统一 `WindowEnvironment`；多窗口/多 view 的状态隔离、关闭和重建可追踪；官方未覆盖的原生窗口行为由宿主集成测试兜底。([Flutter add-to-app](https://docs.flutter.dev/add-to-app)、[Apple Scenes](https://developer.apple.com/documentation/uikit/scenes)、[HarmonyOS lifecycle](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/window-lifecycle/)) |
