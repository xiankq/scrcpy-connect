# 能力接口与状态收敛

Status: complete

## 目标

完整处理全局命令、动态参数、重复校验和能力职责混杂；以清晰的能力接口替代应用内部模拟协议。页面、路由、控件、Hooks 和渲染租约继续由 Widget 持有；状态使用 hooks_riverpod 与 flutter_hooks，必要的不可变状态及值模型使用 Freezed。

## 完成条件

- 应用内部通过能力所属的命名 Dart 操作调用；移除全局字符串/枚举加动态 Map 的业务分发，以及资源模块持有的全应用请求回调。
- 参数与结果按实际业务概念类型化。JSON 仅用于真实平台/伴生协议、持久化和明确的适配入口；命令规则跟随其所有者，删除集中式 command_contract。
- 结构校验仅在数据进入对应适配入口时执行；权限、连接代际、精确资源归属和执行结果核验保留在能力所有者，副作用前的拒绝顺序不得退化。
- 每份状态只有一个来源。能力 Notifier 可独立消费依赖；应用聚合只组合只读状态。取消、迟到回执、资源关闭失败及重试、状态恢复和依赖替换均保持现有保证。
- 删除无调用者的兼容层、转发层和重复规则；目录与类型按实际职责收敛，不以拆文件或缩行数作为完成依据。
- 全局伪命令不能继续成为生产依赖；后续按需新增的测试通过与生产相同的能力接口验证行为。
- 架构检查可拦截全局动态分发回流、业务反向依赖启动装配、普通实现直接依赖 Riverpod、core 持有视图操作等问题。
- 按当前用户要求清除既有测试、夹具和驱动；后续只按需补充必要测试。运行静态分析、架构检查、生成一致性及格式检查。真实设备验证以当时可用设备与可执行环境为准，如缺少证据须明确报告。

## 审计范围

当前涉及 application、devices、control、media、content、files、clipboard、settings、identity、companion、platform，以及其页面、共享控件、Hooks、路由、启动装配和测试调用者。已有大范围未提交变更属于当前工作树，持续保留。

## 迁移顺序

1. 收紧资源依赖：内容读取、缓存租约、缩略图与媒体捕获，先移除全局回调和反向分发。
2. 将设备/连接、控制/音源、内容/文件、设置/身份、平台适配分别收敛为命名操作与领域参数/结果；迁移状态和页面消费者。
3. 移除应用命令总线及集中校验；应用层保留真正的生命周期、状态恢复、快照与跨能力协调。
4. 审计剩余宽接口、动态转换和重复规则，补架构门禁并完成全部验证。

完成必须逐条核对上述条件；局部迁移通过测试不表示整体目标完成。
