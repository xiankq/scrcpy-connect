# 应用实现

修改行为先读[产品规格](../../designs/prod/README.md)，修改视觉先读[设计约束](../../designs/AGENTS.md)。

## 状态与能力

- `core/<能力>/` 按应用能力聚合基础逻辑、状态、专用模型、序列化与持久化；生成文件跟随源文件。跨能力共享的类型优先归定义其规则的所有者。可复用原生能力仍归 `packages/`，应用适配代码跟随所服务的能力。
- 定义依赖、查询与派生值的 Riverpod 文件使用 `*_provider.dart`；状态所有者使用 `*Notifier` 类及 `*_notifier.dart`。普通 Dart 实现按实际职责命名，通过参数接收依赖；同一能力可以同时包含两者。
- 视图操作放在 Widget 文件中：导航、弹窗、提示、焦点、选择器、滚动、动画、渲染及视图租约由 Widget/Page 持有并负责生命周期。页面局部交互状态通过 Flutter Hooks 就近维护；将可见性、焦点和选择结果作为数据交给 core。
- `core/` 通过结果、状态与数据事件表达业务变化，不持有 Flutter 视图依赖，不依赖页面、路由、控件、视图 hooks、视觉定义或启动装配。启动装配归 `bootstrap/`；`core/application/` 负责应用生命周期、会话订阅、快照恢复与跨能力协调，操作规则跟随所属能力。缓存、任务与底层资源跟随实际所有者，页面结束只释放其订阅及租约。
- 同一份状态保持一个来源。能力 Notifier 可独立使用，跨能力快照只组合只读投影；传输订阅及关闭由同一 scope 所有者统一管理，状态校准先于页面事件。按实际复用、独立替换点或资源所有权抽取，直接命名其数据或能力；简单调用就地完成。
- 应用内部调用所属能力的命名 Dart 操作，参数与结果使用领域类型；平台/伴生协议、持久化与事件或视图快照适配才使用 JSON。能力实现通过参数接收明确依赖，不持有全应用请求回调或依赖会话装配。全局命令枚举、动态业务分发及集中式命令契约由架构检查拒绝。
- 文件名表达主要公开类型或共同业务语义；同一契约的模型、接口、执行句柄和回收失败可同文件，辅助实现私有化。按实际复杂度细分能力目录；`utils/` 只放无业务身份的通用纯函数。

## 页面与视觉

- 页面按路由语义嵌套，入口使用完整语义的 `*_page.dart`；专属控件与交互助手就近放置。页面组合可独立理解的交互与呈现单元，跨页面复用成立后再提升到 `widgets/`。
- 路由沿用 `router/app_router.dart` 的 typed route；导航动作通过 `router/navigation.dart`，资源解析通过 `router/route_resource_resolver.dart`。调整路由同时核对返回、深链及资源失效的行为。
- 非控件视觉定义归 `styles/`；组件消费语义 token。视觉数值唯一维护在 [design.md](../../designs/design.md)，通过[生成器](../../scripts/design_tokens/README.md)更新 `styles/generated/`。
- 修改共享控件时核对设计稿母组件及受影响实例；运行态检查明暗主题、窄容器、大字、安全区和辅助偏好。GPU 效果以实际渲染取证。
