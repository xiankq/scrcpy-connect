# 应用代码（app/lib）

改行为先读[产品规格](../../designs/prod/README.md)，改视觉先读[设计规则](../../designs/AGENTS.md)。标「（自动检查）」的规则由 `dart --disable-dart-dev scripts/check_architecture.dart` 检查，违反会报错。

## 目录

| 目录 | 放什么 |
| --- | --- |
| `core/<能力>/` | 一项应用能力的逻辑、状态和持久化，例如 `core/files/`。文件必须放在某个能力目录下（自动检查）。 |
| `bootstrap/` | 应用启动时的依赖装配。 |
| `pages/<功能>/` | 页面，按用户要完成的任务分目录。 |
| `widgets/`、`hooks/` | 被两个以上页面复用的控件和 Flutter Hooks。 |
| `router/` | 路由定义、导航动作、路由资源解析。 |
| `styles/` | 不属于某个控件的视觉定义（主题、动效、字体）。 |
| `utils/` | 不含业务概念的通用纯函数，例如 `formatters.dart`。不能导入业务代码（自动检查）。 |

- 多个能力共用的类型，放在定义它规则的那个能力里。
- 可被其他应用复用的原生能力放 `packages/`；只为本应用做的适配代码放在它服务的 `core/<能力>/`。
- 能力目录按实际文件数量再分子目录，文件少就不分。

## core 与状态

- `core/` 用返回结果、状态和数据事件告诉外界发生了什么。`core/` 不导入 Flutter 视图、页面、路由、控件、视图 hooks、`styles/` 或 `bootstrap/`（自动检查）。
- 生命周期、事件、恢复、活动汇总各有独立目录（`core/lifecycle/`、`core/events/`、`core/recovery/`、`core/activities/`）。具体功能的规则写在该功能自己的能力目录里，不写进这些公共目录。
- 应用自有的名称统一用 `App` 前缀，例如 `AppBootstrap`、`AppButton`。其他类型和文件按它实际做的事命名。
- 每份状态只有一个来源。能力的 Notifier 能单独使用；需要组合多个能力的快照时，只读取各能力的状态，不另存一份。
- 传输订阅的建立和关闭由同一个 scope 负责。收到传输数据后，先更新状态，再向页面发事件。
- 缓存、任务和底层资源由创建它们的能力持有。页面退出时只释放自己的订阅和租约（租约：页面占用、退出时必须归还的资源，例如 `hooks/use_transfer_cache_lease.dart`）。

## 命名与文件

- 定义依赖、查询、派生值的 Riverpod 文件命名为 `*_provider.dart`。持有状态的类命名为 `*Notifier`，文件为 `*_notifier.dart`，一个文件一个 Notifier（自动检查）。
- 普通 Dart 类按职责命名，通过构造参数接收依赖，不导入 Riverpod 或 provider/notifier 文件（自动检查）。同一能力目录里可以同时有两类文件。
- 纯数据、序列化类型和不可变状态放在所属模块的 `models/`（自动检查）。生成文件（如 `.freezed.dart`）和源文件放在一起。只给某个页面用的展示模型放在该页面目录的 `models/`。
- 数据校验和纯计算可以写在模型里。接口、取消令牌、执行中的任务、持有活连接或回调的上下文、资源句柄不放 `models/`，和使用它们的类放在一起。
- 文件名写主要公开类型或这组类型的共同用途（自动检查文件名与主类对应）。同一份数据格式的多个模型可以放一个文件。能力接口文件可以导出它的公开模型；执行句柄和清理失败类型跟接口或实现放在同一文件。

## 调用能力

- 应用代码调用所属能力的具名 Dart 方法，参数、结果、事件和快照都用该能力的不可变类型。JSON 只出现在平台通道、伴生程序协议和持久化的适配代码里。
- 能力实现通过参数接收明确的依赖，不持有全应用的请求回调，不依赖会话装配。全局命令枚举、按字符串动态分发业务、集中式命令表都会被拒绝（自动检查）。
- 只在三种情况下抽出新的类或函数：代码真的被多处复用、需要可替换（如测试替身）、需要单独持有资源。名字直接写它处理的数据或能力。简单调用直接写在原处。

## 页面

- 页面入口文件命名为 `*_page.dart`，与 Page 类名对应；不加 `index/` 目录（自动检查）。
- 功能独立的页面放自己的目录，即使 URL 是嵌套的，例如 `/devices/:id/files` 的页面放 `pages/files/`，不放进 `pages/devices/`。
- 页面专用的控件、交互函数、provider 和模型放在页面目录里。被第二个页面用到时再移到 `widgets/`。
- 页面需要派生展示数据时加专属 provider；页面有自己生命周期的异步流程（如一次连接尝试）时加 Notifier。被多个页面用到的业务状态和操作放 `core/`。
- 焦点、选中项、滚动、动画这类局部交互状态用 Flutter Hooks 写在控件里。
- 导航、弹窗、提示、选择器、渲染和租约由 Widget/Page 持有，并在 Widget/Page 销毁时释放。

## 路由

- 路由使用 `router/app_router.dart` 的 typed route。页面跳转调用 `router/navigation.dart`，路由参数转资源用 `router/route_resource_resolver.dart`。
- 改路由后核对三件事：返回键回到哪里、深链能否打开、路由指向的资源（如设备）失效时页面怎么处理。

## 视觉

- 控件用按用途命名的 token 取颜色、字体和尺寸：`AppColors`、`AppTypography`（`styles/theme.dart`）和 `DesignTokens`（`styles/generated/design_tokens.g.dart`）。不写颜色字面量，`generate.mjs --check` 会报出硬编码颜色。
- 视觉数值只在 [design.md](../../designs/design.md) 里改，再按[生成说明](../../scripts/design_tokens/README.md)重新生成 `styles/generated/`。
- 改共享控件时的设计稿核对和运行验证项见[设计规则](../../designs/AGENTS.md)。

## 失败与诊断

- 能力层把可恢复的故障转成带操作名的结果，例如"发送文件失败：目标目录不存在"。
- Notifier 遇到失败时保留已有数据，发布"失败"或"待核对"状态；页面在出错的位置提供下一步按钮（如「重试」）。
- 意外异常交给 `core/diagnostics/app_diagnostics.dart` 注册的全局错误处理，保留堆栈。
- 日志写动作、阶段和脱敏后的字段，不写设备地址、序列号、文件名等原值。
- 串行异步队列可以在内部等待链上吞掉已经处理过的错误，但原调用方必须仍收到失败。
- 后台订阅、主动刷新和任务清理的失败，必须变成状态、事件或诊断日志中的一种，不能静默丢弃。
- 插件缺失、用户取消、允许部分成功的逐项错误，按该接口文档写的约定返回。
