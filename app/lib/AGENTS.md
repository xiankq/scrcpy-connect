# 主控应用

- 页面布局、命名、typed route与焦点按[导航](../../docs/implementation/flutter-navigation.md)；用户行为按[产品规格](../../designs/prod/README.md)。
- `stores/` 保存并提供状态、变量及其读写、校验和派生逻辑；provider 可以组合 service 来完成数据操作。`services/` 封装与视图无关的数据处理、持久化、通信及原生能力。两者通过数据、结果和事件交互，不操作视图。
- Widget/Page 组织 store、service 与用户操作，持有弹窗、导航、焦点、选择器、页面可见性、渲染和视图租约的逻辑及生命周期；页面局部状态就近放在 widget 或 hook 中。
- 保持 `pages/<页面>/` 的路由入口与页面专属 `widgets/` 结构；按可独立理解的交互或呈现拆分大型页面，页面负责组合，专属控件不提升为全局控件。
- `stores/`、`services/` 保持扁平，相关文件使用共同的业务前缀（如 `file_`）。文件名与主类使用一致的含义；每个文件只放一个公开主类及其私有辅助类、函数。公开数据类型归 `models/`，真实可替换的能力接口独立命名。
- 按实际复用、资源所有权和生命周期决定抽取；同一份状态只有一个来源。名称直接说明负责的数据或能力，删除纯转发层，避免为命名或分目录额外包装 class。
- 主题与非控件视觉定义归 `styles/`，跨页面共享控件归 `widgets/`，页面专用控件留在对应页面的 `widgets/`；控件配套的几何、反馈等实现就近维护。
- 数值和视觉角色唯一维护于[视觉规范](../../designs/design.md)，通过[生成器](../../scripts/design_tokens/README.md)输出到 `styles/generated/`；组件使用语义 token，生成文件不手改。
- 共享控件改动同步设计稿母组件及实例，核对明暗主题、窄容器、大字、安全区和辅助偏好。实时 GPU 与 Ardot 静态稿分别取证。
