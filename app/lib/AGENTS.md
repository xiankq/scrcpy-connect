# 应用实现

修改行为先读[产品规格](../../designs/prod/README.md)，修改视觉先读[设计约束](../../designs/AGENTS.md)。

## 状态与能力

- `core/<能力>/` 按应用能力聚合逻辑、状态与持久化。跨能力共享的类型归定义其规则的所有者；可复用原生能力归 `packages/`，应用适配代码跟随所服务的能力。
- 纯数据、序列化类型与不可变状态放在所属模块的 `models/`，生成文件跟随源文件；页面专用展示模型放在页面模块的 `models/`。数据校验和纯计算可随模型维护；接口、取消令牌、执行任务、带存活连接或回调的上下文、资源句柄跟随其所有者。
- 定义依赖、查询与派生值的 Riverpod 文件使用 `*_provider.dart`；状态所有者使用 `*Notifier` 类及 `*_notifier.dart`。普通 Dart 实现按实际职责命名，通过参数接收依赖；同一能力可以同时包含两者。
- 页面可用专属 provider 派生展示数据、用 Notifier 编排有独立生命周期的异步流程，按复杂度引入，沿用 provider/notifier 命名。复用的业务状态与操作归 `core/`；焦点、选择、滚动、动画等局部交互通过 Flutter Hooks 就近维护。导航、弹窗、提示、选择器、渲染及视图租约由 Widget/Page 持有并负责生命周期。
- `core/` 通过结果、状态与数据事件表达业务变化，不持有 Flutter 视图依赖，不依赖页面、路由、控件、视图 hooks、视觉定义或启动装配。启动装配归 `bootstrap/`；生命周期、事件、恢复及活动汇总按职责独立，功能规则归所属能力。应用名称统一使用 `App` 前缀，类型与文件优先表达实际职责。缓存、任务与底层资源跟随实际所有者，页面结束只释放其订阅及租约。
- 同一份状态保持一个来源。能力 Notifier 可独立使用，跨能力快照只组合只读投影；传输订阅及关闭由同一 scope 所有者统一管理，状态校准先于页面事件。按实际复用、独立替换点或资源所有权抽取，直接命名其数据或能力；简单调用就地完成。
- 应用内部调用所属能力的命名 Dart 操作，参数、结果、事件与快照使用所属模块的不可变领域类型；JSON 仅用于平台、伴生协议与持久化适配。能力实现通过参数接收明确依赖，不持有全应用请求回调或依赖会话装配。全局命令枚举、动态业务分发及集中式命令契约由架构检查拒绝。
- 文件名表达主要公开类型或共同业务语义；同一数据契约的模型可同文件，能力接口可导出其公开模型，执行句柄和回收失败随接口或实现维护。按实际复杂度细分能力目录；`utils/` 只放无业务身份的通用纯函数。

## 页面与视觉

- 页面按用户任务与功能组织，入口采用对应 Page 类的 `*_page.dart`，目录表达所属功能，文件名表达自身职责；独立功能不因 URL 嵌套而堆在某个入口页面下面，也不增加 `index/` 层。专属控件、交互助手、provider 与模型就近放置，跨页面复用成立后再提升到 `widgets/`。
- 路由沿用 `router/app_router.dart` 的 typed route；导航动作通过 `router/navigation.dart`，资源解析通过 `router/route_resource_resolver.dart`。调整路由同时核对返回、深链及资源失效的行为。
- 非控件视觉定义归 `styles/`；组件消费语义 token。视觉数值唯一维护在 [design.md](../../designs/design.md)，通过[生成器](../../scripts/design_tokens/README.md)更新 `styles/generated/`。
- 修改共享控件时核对设计稿母组件及受影响实例；运行态检查明暗主题、窄容器、大字、安全区和辅助偏好。GPU 效果以实际渲染取证。

## 失败与诊断

- 能力层把可恢复故障转成带操作语义的结果。Notifier 保留已知数据并发布失败或待核对，页面提供就近动作。意外异常交给应用错误边界，保留堆栈。日志记录动作、阶段与脱敏字段。
- 异步串行队列可以在派生等待链上吸收已结算的错误，原调用仍收到失败。后台订阅、主动刷新和任务清理的失败要有状态、事件或诊断归属。插件缺失、用户取消及允许部分完成的逐项错误按接口契约处理。
