# 产品与视觉设计

## 责任来源

- 产品入口、对象归属和状态转换由 [prod/README.md](prod/README.md)指向的规格决定；视觉说明不另定产品行为。
- [design.md](design.md)的 token 与正文定义视觉数值及其用途。Pencil implementation 变量是这些 token 的映射，Flutter 常量由[生成工具](../tool/design_tokens/README.md)产生；两者均不独立选值。
- 修改玻璃用途、成像或动效前，读取 [Apple 材料研究](../docs/research/liquid-glass-design-review.md)及对应官方来源，区分原生原则、本项目实现和验证边界。

## 稿件与组件

`mobile.pen` 是唯一页面源稿。使用 Pencil MCP 读写；MCP 不可用时使用 `pen interactive` 对象 API，禁止按文本读取或修改 `.pen`。

共享材料、导航、标题、内容行与开关由母组件维护；页面实例覆盖业务文案、图标、启用状态及明确变体。普通内容行的差异不构成复制一套材质或组件的理由。新增页面先核对现有组件的职责。

每个完整页面使用独立顶层 Frame；规范、组件与局部状态按各自底板独立成顶层画布，保存在同一 `mobile.pen`，不再用超大外层 Frame 包住全部页面。独立 Frame 可以表示同一页面的正常、失败、抽屉或系统授权示意，不按 Frame 数量新增路由。远端屏幕和系统弹窗示意与主控自身界面分开，远端内容保留原应用外观。

布局按父容器约束和内容流工作。绝对定位用于远控画面、遮罩及浮动操作等叠加关系；普通内容使用 Flex 流。标记为 `scroll-viewport` 的裁剪保留完整滚动内容，核对其末项可达；其他活动分支的裁剪应作为布局问题处理。

## 变更核验

逐页复核信息层级、对齐、颜色语义、材料用途和组件引用，不用一个代表页面代替受影响页面的检查。标题与普通内容行的精简遵循[内容呈现规则](prod/interaction-rules.md#内容呈现与系统偏好)，保留真实任务状态与必要正文。

材料用途与成像分别核对：先确认内容层和浮动控制层的归属，再检查背景透入、轮廓折射、边缘光学响应及文字可读性。仅调整模糊或透明度不能证明达到液态玻璃目标；静态稿也不证明按压形变或生产后端效果。

母组件变更后核对展开实例，覆盖明暗外观、降低透明度、长标题、窄容器及相关远控叠加状态。禁用插槽与当前活动分支分开检查。结构扫描说明引用和边界，实际截图说明视觉，两者分别记录。

`design.md` 变更后执行官方 lint 与 token 漂移检查，入口见[工具 README](../tool/design_tokens/README.md)；修复错误，按来源解释保留警告。静态稿、Widget 截图、真实 GPU 成像和业务运行分别提供证据。

预览导出到系统临时目录。仓库保存源稿、规范、实际引用的素材及其来源；示例照片的用途见[素材说明](assets/README.md)。
