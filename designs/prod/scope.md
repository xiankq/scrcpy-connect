# 功能取舍

让用户在手边的主控设备上继续使用另一台 Android 被控设备的真实应用、内容与通信。优先服务手机控制手机，同时适配平板与桌面。主控始终不要求开启调试；被控无需安装额外 APK，通过系统要求的调试设置与授权建立连接，具体约束见[架构决定](../../docs/adr/)。

保留通话、相册预览和文件管理专用页；短信经通知进入被控手机原应用。录屏与文件／相册自动备份退出范围。

## 被控版本与局部能力

基础整机远控以 Android 5.0／API21 为下限，实际编码器和输入权限在启动时确认。独立应用窗口要求 API29，输出声音要求 API30；这些功能受限不应阻止整机远控、文件或剪贴板。通知、通话按系统实际权限确认，不因接口存在而显示为可用。主控安装条件与被控版本分别判断，当前验证及功能条件见[被控兼容边界](../../docs/implementation/android-target-compatibility.md)。

## 判断原则

手机应用已经完成的阅读、编辑、拍摄和账户管理，优先原应用接续。跨设备浏览、批量选择、内容传输及来电处理具有独立任务价值，保留专用功能页。通知附近能够完成的轻操作就近提供，不扩展成完整业务系统。

完整互联体验由任务能否自然完成来判断，不以复刻厂商全部功能或增加页面数量来判断。手机屏幕与独立应用窗口仍是使用手机应用的主要方式；专用功能页补足高频跨设备任务。

## 保留专用功能页

| 能力 | 保留范围 | 取舍依据 |
| --- | --- | --- |
| 设备与连接 | 设备首页、发现与授权、设备工作台、恢复连接、设备支持说明 | 用户需要知道连接对象与下一步；沿用设备优先结构 |
| 手机屏幕与应用入口 | 整机控制、常用／最近应用、应用列表与搜索、独立应用窗口和会话切换 | 接续已有真实应用与登录状态，不重建应用内部界面 |
| 文件管理与传输 | 目录与分类、搜索、选择、双向手动传输、基础文件操作、任务进度及同名冲突 | 跨设备批量取用与文件管理具有独立价值 |
| 相册预览 | 图片／视频浏览与预览、选择、手动取回和分享 | 查看新内容与手动取用不需要备份计划 |
| 通话 | 来电与通话中状态、接听／拒接／挂断，以及实际支持的声音控制 | 来电处理需要快速操作，主控语音支持另行判断 |
| 通知 | 当前有效通知的轻量列表、设备来源、清除与打开原应用 | 统一提醒入口，短信与其他应用共用，不按应用建设多个中心 |
| 设置 | 全局外观；设备工作台中的连接偏好、剪贴板与导航键；会话附近的画质 | 设置按作用范围就近提供，归属见[信息架构](information-architecture.md) |

## 保留就近操作

截图、键盘和系统分享保留为相关页面上的动作。设备声音随实际打开的控制页面播放，剪贴板由设备工作台的自动同步开关控制，行为见[声音与剪贴板](interaction-rules.md#声音与剪贴板)。原通知已提供的快捷回复、验证码复制等操作，在实际可用时就近呈现。快捷回复不扩展为短信会话列表、新建短信或聊天记录功能。

## 原应用接续

| 内容或操作 | 入口与去向 |
| --- | --- |
| 短信与即时消息 | 通知进入手机控制画面，再进入对应原应用；查看全文、新建消息、查找历史均在原应用完成 |
| 邮件、日历、笔记和其他通知内容 | 同样进入被控手机原应用，不建立主控端的邮件、日历或笔记产品 |
| 主动拨号、联系人、通话记录 | 进入手机电话应用；通话专用页处理当前来电与通话状态 |
| 拍摄、修图和图库整理 | 进入手机相机或相册应用；专用相册页聚焦预览与取用 |
| 文档编辑 | 在手机原应用编辑，或取回副本后用本机应用编辑，再主动传回；不跟踪编辑会话和自动回写 |
| 应用卸载、权限与系统设置 | 进入手机对应设置；应用列表用于启动和切换，不建设应用运维面板 |

通知接续优先复用已有手机控制会话；从应用入口主动打开独立窗口的能力仍保留。通知能定位原内容时直接进入，不能时明确退到应用或手机屏幕。屏幕点亮、锁屏与动作失效见[用户流程](user-flows.md)。

## 移出产品范围

| 能力 | 来源与理由 |
| --- | --- |
| 录屏、录制中心及相关后台任务 | 当前明确移除 |
| 文件／相册自动备份、云相册、备份计划与删除联动 | 云相册亦不属于当前内容协同目标 |
| 独立短信收件箱、新建短信和短信历史 | 短信通过通知与手机原应用处理 |
| 联系人同步中心 | 选择联系人和查看通话记录进入手机电话应用 |
| 自动编辑回写、版本合并及编辑副本管理中心 | 保留取回与主动传回，避免另建文档协作产品 |
| 长期通知档案 | 通知服务于发现事件与接续原应用；不保留长期本地历史 |
| 专用相机拍摄页、虚拟摄像头／麦克风共享、热点管理 | 拍摄交给原应用；硬件共享和网络管理不因厂商支持就自动纳入 |
| 独立应用安装管理、命令终端和日志查看器 | 系统与应用设置由手机原界面承接；保留解决连接问题所需的诊断反馈 |

移出范围是当前产品取舍，不是“做完首版再补”的隐含承诺。被控手机自身的应用仍可通过远控正常使用。

## 竞品依据与证据边界

小米 iPhone 端的通知接续与短信镜像、Windows／Mac 的真实手机应用窗口，支持“应用内容交给原应用”的选择。华为和 vivo 的独立文件入口及照片取用，支持文件、相册的独立任务价值。OPPO、Phone Link 等提供的短信或更多协同能力不构成本项目必须复刻的清单。

详见[小米与华为路径研究](../../docs/research/manufacturer-scope-xiaomi.md)及[厂商流程研究](../../docs/research/manufacturer-workflows.md)。这些是产品体验依据，不代表本项目能力已验证，也不改变被控免安装、主控不要求调试等约束。
