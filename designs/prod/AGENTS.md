# 规格写法

## 改哪个文件

- 从 [README](README.md) 的表里找到负责这项行为的文档，直接改那里的规则。同一条规则只写在一个文档里。
- 新增页面或设置项前，先读[信息架构](information-architecture.md)，确认它放在哪里。
- 改返回、关闭、声音或剪贴板的行为时，对照[交互规则](interaction-rules.md)核对。
- 术语用[词表](../../GLOSSARY.md)里的词。视觉数值写在 [design.md](../design.md)，不写进规格。

## 怎么写

- 每条行为按「触发条件 → 用户看到的结果 → 下一步可以做什么」写，包括失败后怎么恢复。例如：「连接超时时，页面显示「连接失败」和原因；用户可以点「重试连接」或「返回修改」。」
- 只写用户能看到的行为，不写实现方式。
- 功能在某些设备或系统上用不了时，写清三件事：在什么条件下用不了、此时页面显示什么、用户还能走哪条路。
- 设置项只放用户自己做的选择。由系统状态推算出来的值（如"当前是否在线"）作为信息展示，不做成开关。
- 计划要做的能力和已经交付的行为分开写。写"已支持"必须有实际运行验证过的证据。
- 逐段删掉：重复的保证、为设计辩解的背景、标题已经说明的内容。
