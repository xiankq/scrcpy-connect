# 电话接力

工作台的「电话」进入这台设备的电话页：页面显示手机上的通话状态，并能打开被控手机的原电话界面；在能力验证通过时，还可以在主控上接听和进行当前通话（电话接力）。当前已交付的只有电话页和「打开手机电话」这条路径，见[平台与能力](compatibility.md#当前交付边界)。本文的接听、通话中、声音交接部分是待验证的目标。

## 能力与入口

能力按主控平台、被控设备、当前用户、通话类型（蜂窝或网络通话）逐项核对，包括：来电观察、接听／挂断控制、下行声音、麦克风上行、声音交接。页面只提供本次核对通过的操作。

| 当前情况 | 入口与结果 |
| --- | --- |
| 没有已核对的通话，或设备只支持打开原电话应用 | 电话页显示「打开手机电话」，点按后打开手机电话界面，优先复用已有整机画面。拨号、查联系人、通话记录都在原应用里完成 |
| 观察到来电或通话，由手机接听 | 工作台的来电入口显示来电者、已核对的身份和声音所在设备，提供「在手机画面接听」或「打开手机通话界面」。接听和挂断由用户在手机画面里操作 |
| 已核对是同一通话，且完整接力能力可用 | 进入电话页。响铃时提供「在此接听」和手机画面路径；接通后提供已核对的静音、声音选择和挂断 |
| 观察或连接已失效 | 停止旧通话的操作，显示待核对。连接仍可用时核对同一通话；连接中断时先检查连接 |

「电话」入口：

- 在工作台快捷入口中的位置固定。
- 打开原应用或手机通话界面后结果无法确认时，显示「电话界面待核对」，可以查看原设备画面；查看时核对的是同一次请求。
- 确认失败时，在原位显示原因和可用的重试或检查连接。
- 原应用里已经在进行的通话，声音能力验证通过后可以转到主控。

来电提示：

- 前台有新来电时，先显示紧凑的来电提示，突出来电者并显示来源设备。点按后按能力进入电话页，或直接打开手机通话界面。
- 来电提示不打断当前任务，不抢键盘焦点。其他设备的来电显示为带来源的独立提示。
- 在后台时，按「来电提醒」偏好和平台实际能力处理，系统提醒用通用文案。
- 读不到来电者身份时显示「来电者未知」。头像只用已核对身份提供的头像。

通话入口统一：

- 有真实来电或通话时，工作台主按钮下方显示一条通话入口。工作台入口、来电提示、能确认是同一通来电的通知，都进入同一个处理路径。
- 完整接力使用独立电话页，保持主控主题。返回、换页、切换设备只离开这个页面，通话继续。
- 没有验证完整接力时，来电入口直接打开手机通话界面。
- 点系统提醒只负责进入页面或核对；接听由用户在对应界面明确点按。

## 接听与通话中

「在此接听」表示用主控的麦克风和扬声器（或当前耳机）接听：

1. 第一次点按时才申请主控麦克风权限。用户拒绝后，仍可打开手机画面接听。
2. 接听前准备音频，核对来源设备和仍在响铃的是同一通来电。准备期间显示「正在准备接听」，可以取消；还没接听时取消，不会挂断手机上的来电。
3. 准备失败时不自动改为在手机接听。
4. 提交前来电已结束或被另一通来电替换时，撤销这次操作，不作用到新来电上。
5. 提交后显示「正在接听」。收到接通回执后更新通话阶段；声音输出位置按声音路由回执单独更新。通话计时从真正接通时开始。
6. 已接通但声音失败时，显示「已接通，声音未接通」，保留手机接续和挂断。

拒接和挂断作用于当前能可靠定位的那通电话。结果未知时，在同一位置提供核对；刷新和重连只读取结果，不重发。

电话页布局（视觉见[通知与电话](../design.md#通知与电话)）：

- 来电者身份、来源和实际阶段在固定位置。
- 响铃时：底部左侧「拒接」，右侧「在此接听」，下方「在手机画面接听」。
- 准备或提交期间：原操作区显示当前阶段和可用操作。
- 接通后：底部换为麦克风和声音输出，挂断单独在下方。麦克风静音控制对方能否听到；声音输出只列出已验证的设备。
- 窄屏、大字号、低高度窗口下，所有操作都能滚动到。
- 返回保留当前通话和入口；只有挂断才结束通话。

声音交接：把声音切回手机、或转到这台主控，都作用于同一通电话。系统确认目标音频线路就绪后，才切换显示并释放原线路。失败时保留仍可用的线路，提供重试。不支持切回时，提供「打开手机电话界面」，声音位置不变。

## 中断与恢复

- 首个版本每台主控同时只接力一通电话。存在其他通话、来电等待或无法区分是哪一通时，打开手机电话界面处理。新来电出现时，已有通话保持不变。
- 通话声音独立运行。接力开始前，暂停本应用其他设备的声音和媒体预览；结束后恢复用户之前开启、仍然有效的播放。
- 主控来电、音频焦点丢失、耳机拔出、麦克风权限被撤回或网络中断时，就地更新接收、麦克风和声音位置的状态。改为外放由用户自己选择。
- 连接中断时显示「手机通话状态待确认」，暂停主控麦克风和远端通话操作。系统确认声音回到手机后，才显示声音在手机。重连后先核对原通话和音频线路，再由用户决定是否继续接力。
- 前台接力按平台实际能力提供。未验证的后台组合，进入后台后只按系统事件显示状态。系统来电界面、耳机按键、锁屏接听分别验证后再提供入口。

## 交付与验证门槛

- 当前只交付打开手机系统通话界面的路径，见[平台与能力](compatibility.md#当前交付边界)。
- 完整接力的设计稿标为「待验证目标」。运行中的产品只显示实际可用的能力和操作，不出现研发说明、假开关或「即将支持」之类的空入口。
- 按主控、被控、通话类型分别记录实测结果。测试覆盖：真实接听和对方挂断、双向声音、回声与延迟、静音、声音交接、锁屏和后台、耳机变化、重连、快速换来电。只有实测通过的功能和组合才在页面上提供。

音频能力参考 [scrcpy 音频文档](https://github.com/Genymobile/scrcpy/blob/master/doc/audio.md)。
