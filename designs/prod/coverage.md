# 产品流程与设计状态覆盖

本表记录产品流程的代表设计状态及仍需补齐的证据。页面 ID 用于在 [mobile.pen](../mobile.pen) 定位，不等于独立路由或功能完成状态。源码中的页面、后端能力、静态设计与物理设备效果分别验收。

下表“已有”仅表示存在代表状态；剩余项不能因无关实验、按钮存在或页面计数自动关闭。产品行为按[交互规则](interaction-rules.md)，连接条件按[设备与连接设计](device-connection.md)，内容交付按[内容与传输](content-and-transfer.md)，实际功能限制按[平台与能力边界](compatibility.md)。

## 验收依据

每项交付声明记录被验证的主控平台、被控版本、设备或模拟器、实际入口、权限条件、成功与失败分支及证据层级。以下层级分别成立，不能互相替代：

| 证据 | 能说明什么 | 不能由此推断什么 |
| --- | --- | --- |
| 静态设计与对象扫描 | 状态、组件引用、内容层级及布局目标 | 页面已实现、真实系统授权或连续动效可用 |
| 组件与页面测试 | 指定状态下的交互、路由、文字缩放与约束 | 原生纹理、真实编码器、系统选择器或厂商权限通过 |
| 协议与故障夹具 | 特定错误、取消、迟到结果和恢复不变量 | 物理 USB、真实漫游、OEM 后台或量产安全通过 |
| 普通应用与系统链路 | 该平台实际界面、系统授权、文件或媒体结果 | 同平台全部设备、其他宿主及长时间稳定性通过 |
| 性能与持续运行 | 给定环境与负载的响应、资源和恢复表现 | 原生效果等效、未测场景或其他设备同样达标 |

Android、iOS、macOS 和 Windows 主控的交付分别要求实际整包编译。局部能力缺失可以明确显示受限，但不能破坏其他平台的编译；整包编译通过后仍按各平台实际可用能力与运行证据声明支持范围。

成功路径与拒绝、取消、超时、权限撤销、连接中断、状态失效和结果未知分别核对。文件交付核对独立目标内容及原件保全；跨设备动作核对真正被操作的设备；授权拒绝不能用超时样本代替，清理只处理本次拥有的资源。

恢复场景分别覆盖界面重建、短暂断连、主控进程结束与重新启动。核对未决操作是否仍被保护、迟到结果是否失效、已有活动是否保持归属，不能用同进程恢复代替进程死亡。主动停止不自动复活；需要再次产生副作用时来自新的用户意图。

材质验证区分静态投影、组件截图、真实渲染与物理设备，记录实际渲染器及回退。性能样本声明冷／热启动、前后台、内容变化、声音、画质与设备负载，按同一方法复验；测量端到端响应时明确起止和时钟来源，不能把刻意等待、截图耗时或未解码的纹理事件当作真实呈现延迟。

资料或报告移除不改变尚未验证的状态。没有可核对证据时保留待验，证据过期后重新核对；CI 配置、整包构建与历史其他依赖的结果不能自动关闭当前缺口。
