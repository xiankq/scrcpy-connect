# 设备与连接

本文规定设备的添加、授权、连接、工作台和设备管理。设备记录、配对信任、设备连接和控制会话是四件独立的事（定义见[词表](../../GLOSSARY.md)），界面分别按各自的实际状态显示，不互相推断。例如：有设备记录不代表在线，断开连接不撤销配对信任。

## 设备列表

- 设备按设备记录保存的顺序排列。连接、断开或刷新时，只在原行更新状态和按钮，不重新排序。搜索结果保持原来的相对顺序。
- 每行显示设备形态、名称、当前连接状态和一个按钮。点行进入工作台；点行尾按钮直接「打开屏幕」或开始连接。
- 设备离线时仍可进入工作台，查看本机保存的记录和偏好。恢复在线后不自动打开屏幕，由用户决定。
- 显示最近信息时标注时间。

空列表和搜索：

- 设备记录读完并确认为空时，设备页显示首次添加的内容。点正文里的「添加设备」进入添加设备页，返回后回到同一设备页。
- 有设备时，用页头的搜索和添加按钮。
- 搜索没有匹配时，保留搜索词，提供「清除搜索」。

设备操作菜单（长按、右键或读屏的「设备操作」）：

| 设备状态 | 菜单里的连接项 |
| --- | --- |
| 未连接 | 开始连接 |
| 连接中 | 停止连接（不能再次发起连接） |
| 已连接 | 断开连接 |
| 自动重连等待中 | 显示「等待重连」，提供「停止连接」 |

菜单还包括「连接配置」和「移除」。工作台也提供同样的停止入口。

- 停止或断开连接时：没有进行中的活动就直接停止；有画面、传输等会受影响的活动时，先列出受影响的内容，用户确认后再停止。空闲时的断开不做成危险操作。
- 移除设备始终需要确认。
- 停止连接保留设备记录和已保存的文件。移除记录不撤销手机上的调试授权。
- 名称、型号或 IP 相同，不足以把一条 USB 记录和一条无线记录合并为同一台设备。身份不确定时，保留两条独立记录。

## 添加与发现

添加设备页：

- 从设备列表点「添加」直接进入。四种连接方式按「配对码、扫码、USB、IP 连接」排列，默认打开「配对码」。
- 切换方式时，页头、「附近设备」入口和方式选择器不动，只替换正文；已填写的内容保留。
- 正文先显示该方式的表单、二维码或 USB 状态，下面是简短说明和该方式的帮助入口，主按钮固定在底部。
- 新建连接统一使用本机管理的全局调试身份。添加和连接配置页不提供高级连接选项、私钥来源或专属私钥输入；密钥在全局设置的[授权密钥](#授权密钥)里管理。

附近设备：

1. 「附近设备」放在方式切换上方，点按进入发现页，可刷新。
2. 每个结果显示名称、实际地址端口和信任状态。IPv6 地址写成 `[IP]:端口`。
3. 选中一个结果后回到添加设备页，按该结果对应的方式填入已知字段。直接返回则恢复进入前的方式和草稿。
4. 被发现不代表已授权。

帮助页：每种方式一页，按实际步骤写明每一步在哪台设备上操作。返回后回到原方式，已填字段保留。

离开和返回：

- 来回切换方式，保留本次填写的内容。
- 离开正在等待的扫码或 USB 检查时，停止这次等待，之后迟到的结果不再处理。
- 回到扫码时，使用仍有效的二维码；过期则重新生成。

| 方式 | 底部按钮与流程 | 帮助页内容 |
| --- | --- | --- |
| 配对码 | 「配对并连接」：提交手机地址、配对端口和六位配对码。配对完成后自动查找手机的连接地址并继续连接。配对码过期时，从失败页「返回修改」，地址和端口保留 | 在手机开启无线调试，打开配对码弹窗，照抄地址和配对端口 |
| 扫码 | 进入后主控显示二维码并等待扫描，「重新生成二维码」替换旧码。由被控手机的无线调试功能扫码，主控不需要相机或调试权限 | 在被控手机选择「使用二维码配对」，扫描主控屏幕，处理过期二维码 |
| USB | 「检查连接」开始检查，「重新检查」重新读取授权和设备状态。需要分别取得主控的 USB 访问许可和被控的调试授权；连了多台设备时先选目标；拔线后要重新授权。主控不支持 USB 时就地说明，提供「切到配对码」 | 使用支持数据传输的线，开启 USB 调试，分别在两台设备上确认授权提示 |
| IP 连接 | 「连接设备」：提交 IP 或主机名和连接端口（默认 5555，范围 1–65535）。只适用于已授权且允许按地址连接的设备，只在可信网络使用 | 确认已有授权，查到当前连接地址和端口，再填写 |

- 配对端口和连接端口是两个不同的字段，分别标注；帮助页说明它们在手机上的位置。
- 连接方式和加密条件沿用授权记录或发现结果。
- 跨网络连接走用户已有的 VPN、网关或隧道。

表单校验：提交时有字段需要修改，就在该字段下方显示原因，焦点移到第一个出错的字段。改正后可再次提交。

USB 状态卡（所有反馈在同一张卡内更新）：

| 阶段 | 卡片显示 |
| --- | --- |
| 初始 | 提示接上数据线 |
| 检查中 | 提示：如果出现授权弹窗，在对应设备上点允许 |
| 检测到设备 | 「已检测到 USB 设备」；需要选择时在卡片下列出可选设备 |
| 没有检测到 | 「未检测到 USB 设备」和「重新检查」 |
| 读取失败、主控不支持、已建立连接 | 分别显示原因或下一步 |

卡片内容只反映本次检查的结果。

## 连接过程

提交首次连接后：

1. 显示全屏等待页，底部固定「取消连接」。
2. 配对、查找连接地址、建立连接、核对身份都在这一次尝试里依次进行。只有阶段真的变化时才更新文字。读屏能读到设备和当前阶段；需要在手机上确认时，原位说明怎么做。
3. 无线配对完成后，自动查找与本次授权身份和连接方式相符的地址并连接。
4. 连接成功且身份正确：首次添加直接进入该设备的工作台。可选的设备信息稍后补齐。

取消：点「取消连接」或系统返回，结束这次尝试和之后的自动步骤，回到发起页面并恢复草稿。如果配对已经完成，保留已建立的信任。

失败（找不到地址、授权未通过或无法连接）：停止等待，在同一页显示原因和可用的恢复按钮。正文过长时可滚动，按钮固定在底部。配对得到的授权保留，下次重试可直接使用；查找连接地址仍属于这一次连接。

| 状态 | 页面说明 | 按钮 |
| --- | --- | --- |
| 连接失败（已确认） | 原因，例如未发现连接地址、配对码过期、连接建立失败 | 能改字段时「返回修改」；能直接重试时「重试连接」 |
| 本次授权没完成，尝试已结束 | 需要在手机上允许调试 | 「重新检查」「返回」。还在等待授权时不显示这组按钮 |
| 设备身份不符 | 应答的设备与已保存的设备不是同一台 | 只有「返回修改」。核对目标前不重试，不覆盖已保存的身份 |
| 结果待确认 | 还没确认这次是否连上 | 「重新核对」「返回」。核对不会重发原请求 |

- 核对期间保留原因和实际核对状态。用户发起新尝试时回到等待页。
- 「返回修改」恢复原方式和可用的草稿。
- 首次连接失败后，由用户决定是否重试。
- 迟到的结果只归到它所属的那次尝试，不影响新尝试。
- 本机繁忙、请求排队或容量不足时，不把设备标为离线。诊断里分开显示「本机操作失败」和「设备连接失效」，各自保留原因。

### 保持连接与自动重连

连接意图（应用是否应该保持连接这台设备）：

| 事件 | 连接意图 |
| --- | --- |
| 手动连接成功 | 保存，之后保持连接 |
| 首次连接失败、只添加了记录、只配对成功 | 不保存，不自动连接 |
| 用户停止连接、取消手动连接、从系统通知停止设备活动 | 记为「已停止」；切换前后台或重开应用后仍是已停止 |
| 再次手动连接成功 | 恢复保持连接 |

自动重连：

- 有连接意图的设备暂时断线后自动重连，等待间隔逐步延长，用户随时可以停止。
- 打开应用或回到前台时，恢复仍有效的连接意图。后台是否继续重连见[后台与恢复](interaction-rules.md#后台与恢复)。
- 后台受限或状态待核对时，暂停重连，保留连接意图。
- 授权失效、身份不符或结果未知时，暂停自动尝试，提供检查或重新授权的入口。
- 无线调试的地址或端口变了：可以通过同一可信 GUID 发现新地址。核对是同一台设备、并把新地址可靠保存后，才替换旧地址；加密要求不降低。
- USB 断开后不自动重连。重新插线后仍要选择目标并经过系统授权。
- 上次的设备活动（如显示设置改写）还没确认清理完成时，停止连接或重启应用都保留「待清理」状态。重新开放相关功能前先完成清理；清理结果未知时，显示受限原因。待清理状态不产生新的连接意图，也不恢复用户已停止的连接。
- 连接恢复只恢复通信：不新开画面，不播放声音，不唤醒手机，不重放历史操作。已打开画面的恢复见[屏幕、窗口与输入](interaction-rules.md#屏幕窗口与输入)。

## 设备工作台

已连接、未连接、连接中、连接失败都使用同一个工作台。

设备概览：

- 显示设备名、型号或系统版本、电量图标和已确认的百分比、连接方式图标。
- 工作台在前台可见且设备已连接时，读取 Android 电池数据，每 30 秒刷新。未连接、读取失败或电量未知时显示「—」。正在充电时电池图标带闪电。
- 右侧深色手机轮廓用图标表示连接状态，读屏播报状态。
- 「设备详情」始终可打开；离线时显示的是快照，在详情里标注时间。

主按钮（概览下方，只有一个）：

| 状态 | 按钮 | 点按后 |
| --- | --- | --- |
| 已连接 | 「打开手机屏幕」 | 优先回到该设备已打开的整机画面 |
| 未连接 | 「连接」 | 开始连接，成功后留在工作台 |
| 连接中 | 「取消连接」 | 取消本次连接 |
| 连接失败 | 「重试」 | 重新连接 |

快捷入口（文件、相册、通知、电话）：

- 未连接时位置不变。点按时原地提示「无法打开」和原因。
- 有真实来电或通话时，在概览下方显示一条通话入口，点按回到同一通话。
- 快捷入口和应用宫格都用图标显示，应用使用原图标。功能名和应用名提供给读屏和悬停提示。

常用应用（快捷入口下方第一张卡片）：

- 按设备保存勾选的应用和顺序。
- 为空时点「添加常用应用」直接进入勾选，完成后保存并回到工作台。
- 已有应用时点「编辑」进入管理页：拖动把手排序，读屏可用上移、下移操作。点「选择应用」进入下一级勾选，结果带回管理页：原有应用保持相对顺序，新应用追加到末尾。
- 管理页点「完成」保存；直接返回放弃本次编辑。
- 未连接时可查看和调整已保存的顺序；读取已安装应用需要连接。

正在运行（第二张卡片）：

- 显示手机当前用户正在运行、且已核对的任务，同一应用只出现一次。
- 点图标弹出打开方式，规则见[输入与应用接续](interaction-rules.md#输入与应用接续)。
- 确认没有任务时显示「当前没有正在运行的应用」，仍可点「全部应用」。
- 读取中、读取失败、需要连接时，分别显示实际状态。

工作台上的应用、画面、传输、通话各自负责回到原任务和核对结果。

设备管理（右上角设置图标进入）：

- 包含名称、连接配置、画面与控制、自动剪贴板、诊断、断开和「移除设备」。导航键和屏幕行为在「画面与控制」，「转为 IP 连接」在「连接配置」。
- 改名只改本机记录。偏好的默认值见[比例、清晰度与屏幕偏好](interaction-rules.md#比例清晰度与屏幕偏好)。
- 「移除设备」需要确认，影响见[设备列表](#设备列表)。
- 诊断显示网络、服务、授权、设置的检查结果，可重新检查；编辑连接跳到连接配置页。不提供命令终端。

## 设备详情

- 从工作台进入，是一列「字段：值」的列表，依次为：设备与系统（型号、品牌、硬件、Android/API、安全补丁、ABI、构建、序列号）、电池与电源、屏幕与显示、网络与连接、内存与存储。
- 首次读取较慢时，值的位置显示骨架。刷新期间继续显示已读到的值。
- 电池与电源按 Android 状态区分：充电中、放电中、已接电源未充电、已充满、未知。
- 读取失败、不支持、未知分开显示。某一组读取失败时，其他组照常显示。离线快照标注时间。
- 连接诊断把连接检查、处理入口和功能检查平铺显示。

## 设备连接配置

- 从工作台打开，显示当前已授权的方式和已知字段。
- 修改地址时，沿用原来的协议和设备身份。
- 重新授权：选择对应方式，核对是同一台设备，成功后更新原记录。
- 当前连接支持转为 IP 时，显示「转为 IP 连接」，执行前说明影响。
- 取消时原配置不变。

## 记录迁移

导入：

1. 选择文件后先预览：将新增哪些设备记录，以及可选的全局偏好更新。默认沿用本机设置，已有设备的偏好保留。
2. 新记录保留序列号和可信 GUID。导入的设备在重新授权成功前保持断开；重新授权时核对身份。
3. 画质、电源和剪贴板设置需要在本机重新设置。
4. 重复导入同一文件时，显示已有结果。提交结果未知时，先核对再继续。

- 从选择文件到预览、提交、界面刷新完成之前，不能再次发起导入或导出。
- 导入已完成但界面刷新失败时，明确告诉用户导入已生效，提供只重新加载本机记录的操作，不要求重新导入。
- 导出和分享只由用户发起。

## 授权密钥

全局设置里显示主控授权身份的指纹，提供导入和重置。

- 默认由本机生成并保管，不随云备份或设备记录迁移。
- 导入：多行文本或文件都填入同一个输入框，选文件不会直接提交。校验格式 PEM、Base64，大小不超过 32 KiB，必须是 RSA-2048、指数 65537。输入无效时保留旧身份。已有私钥不回显。
- 重装应用或换一台主控后，默认需要在手机上重新授权；恢复设备记录不恢复调试信任。用户显式导入同一密钥时例外，但这会让不同安装共用手机上的授权。
- 替换或重置前，列出使用全局身份的连接和活动并确认。使用设备专属身份的连接不受影响。
- 新建连接一律使用全局身份，不提供按设备自定义。已有记录保留它绑定的身份，普通的连接编辑不更换密钥。
- 私钥不出现在普通设置导出、设备记录、快照或事件里。

## 转为 IP 连接

1. 从已授权的连接发起。点地址行打开选项弹层，只列出设备当前网络接口的地址；没有地址时可重新查找。
2. 选择后回到转为 IP 连接页，等待用户确认。确认框说明：会重启调试服务、打断进行中的活动、不使用无线调试的加密。
3. 确认后，经原连接在手机上打开端口，用同一身份验证成功后更新原记录。

- 失败或取消时，原字段不变。
- 端口可能已重启但结果未知时，先核对，不自动重试，也不显示成功。
