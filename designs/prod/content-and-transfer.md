# 内容与传输

本文规定手机文件的浏览与操作、相册、主控与手机之间的手动传输，以及把取回的文件交给主控系统（打开、保存、分享）。操作对象和提交反馈的通用规则见[内容保护与提交反馈](interaction-rules.md#内容保护与提交反馈)。

## 文件与目录边界

文件页支持：按目录或分类浏览、新建文件夹、重命名、删除、手动取回。

通用规则：

- 每个操作显示真实的来源、目标和路径。删除和替换先说明影响。操作提交后，切换页面或设备不会改变操作对象。
- 无法读取、未知、空目录三种情况分开显示。到达数量上限时，显示实际读取了哪些范围。
- 遍历目录时不进入子目录里的符号链接。主共享存储根目录的别名路径（如 `/sdcard`）单独识别。手机上无法在主控表示的文件名，不改成另一个名字去操作。
- 打开、修改或取回前，重新核对文件身份、类型和是否可访问。传输过程中源文件变了，不把前后两部分拼成一个文件。目录批量操作逐项反馈结果。

点按条目（浏览态）：

| 条目 | 结果 |
| --- | --- |
| 图片（来自文件列表、宫格、搜索结果或相册） | 进入图片预览；返回时回到原目录或相册位置 |
| 其他文件 | 进入文件详情页，显示文件标识和真实属性 |
| 文件夹 | 进入该目录 |

目录浏览：

- 文件夹排在前面，连续排列，不加组标题和计数。默认四列自适应宫格，可切换为列表；切换时保留选择。
- 打开未读取过的目录时，先显示路径，内容区显示与当前视图一致的占位。
- 在同一次浏览中，已读过的上级目录保留在内存里：返回时直接恢复列表和滚动位置；回到共享存储首页时恢复原来的筛选。
- 收到目录变更、连接变化或用户点刷新时，重新读取目录；期间继续显示上次的条目，新结果到达后原位更新。
- 只有整次读取成功且确实没有条目，才显示空目录。读取失败时原地提供可用操作。

浏览态的页面元素：

- 页头或目录内有搜索。类型入口只在共享存储首页显示。
- 底部液态玻璃栏有「发送」「视图与排序」「更多」。
  - 「发送」：打开来源选择页，列出当前平台可用的文件／文件夹入口。选好来源后，核对文件、目标设备和目标目录（可浏览并更换目标目录），点确认才提交。
  - 「更多」：从按钮向上展开，包含新建文件夹、选择、刷新。
- 排序可按名称、大小、修改时间、类型，可选升序或降序；文件夹和文件分别排序，值未知的条目排序结果保持稳定。视图和排序保存在本机。
- 文件夹显示完整日期；文件显示月／日；大小最多两位小数。
- 点搜索旁的路径入口可跳到上级目录。返回键先回到父目录，到根目录再退出文件页。选择态下的返回规则见下文。

### 文件选择与批量操作

列表和宫格使用同一套选择规则。

进入选择态：

- 浏览态「更多」里的「选择」：进入选择态，0 项选中。键盘和读屏可用同一入口；每个条目另有「选择此项」辅助操作。
- 触摸长按、鼠标右键或主键长按一个可操作的条目：进入选择态并选中该项。已在选择态时，这些操作不会取消已选项，也不先弹出上下文菜单。

选择态中：

- 点条目任意位置切换勾选，文件夹也只切换勾选，不进入目录。不可操作的条目不能选，并显示原因。
- 页头：左侧返回变为关闭（×），中间显示「已选择 N 项」，右侧只有一个全选图标按钮。未全选时点按全选；全部选中后图标变为取消全选。不显示文字，悬停提示和读屏名称分别为「全选」「取消全选」。大字号下页头随内容增高。
- 取消所有勾选后仍在选择态，显示「已选择 0 项」，需要点关闭或返回才退出。
- 全选的范围：当前目录、当前筛选下所有已核对的可操作条目，包括滚出屏幕的。不包括子目录里的内容和筛选外的条目。读取受限时显示范围提示，全选只处理本次确认的条目。
- 进入或退出选择态不改变条目的布局、尺寸和文字截断。列表的选择标记替换行尾箭头的位置；宫格的选择标记叠在缩略图正中。勾选状态不能只靠颜色区分。标记样式和点击区域见[列表](../design.md#列表)。
- 选择期间，设备、路径和筛选固定不变，批量栏上方显示当前目录。目录内容变化时，移除已失效的勾选。断线时保留可见的勾选，重连后重新核对再允许提交。
- 选择状态只属于当前文件页和来源设备，不跨设备、不跨进程恢复。

批量栏（底部悬浮液态玻璃栏）：

- 「取回原文件」「删除」「更多」，图标和文字都用标准文字色。
- 0 项选中或不满足条件时，「取回原文件」和「删除」禁用并说明原因。
- 「更多」向上展开：「重命名」（只在选中一项时可用）、「切换为列表」或「切换为宫格」。切换视图保留选择、筛选和目录，不改变操作对象。

删除：

1. 点「删除」，在当前页打开确认弹窗，显示项数和来源设备，按钮为「取消」和「同意」。
2. 「取消」：关闭弹窗，勾选保留。「同意」：提交这一批删除。
3. 提交后条目保留并标为待确认。确认删除成功的条目才移除；失败的条目继续显示，附逐项结果和原地恢复入口。

退出选择态（系统返回、Escape、页内关闭作用相同）：

1. 有菜单或确认弹窗时，先关闭它。
2. 否则退出选择态：清空勾选，恢复浏览底栏，保留当前目录、滚动位置、筛选和视图。
3. 再按返回时按浏览态规则处理。

已提交的传输或文件操作不会因退出选择态而撤销。退出后可以切目录、筛选、搜索、新建、发送和刷新。

可达性：底栏和展开菜单避开安全区；正文能滚到最后一项，不被悬浮栏遮挡。键盘和读屏能进入选择、切换勾选、全选和退出，播报内容包括条目名、勾选状态和已选项数。

## 名称搜索

- 独立的列表页。来源设备和起始目录固定，退出后回到原浏览状态。
- 范围选项「当前目录及其子目录」「手机内部存储」（即主共享存储 `/sdcard`）与类型选择排在同一行，默认「当前目录及其子目录」。
- 类型字段显示当前选项，点按打开选项弹层：全部类型、图片、视频、音频、文档、压缩包、文件夹。
- 名称关键词和具体类型至少填一项。名称按子串匹配，不分大小写；不搜索正文，不支持拼音或字符规范化匹配。

搜索过程：

1. 「搜索」按钮固定在底部。修改条件时，已显示的结果保留。
2. 提交后逐步显示匹配结果和已检查的数量。每条结果标明完整的父目录，打开前再核对对象。
3. 读取失败、跳过链接或到达上限时，保留已有结果并说明哪些范围没查到。
4. 全部检查完且没有匹配时，显示空态。
5. 点停止：保留已有结果。离开页面：结束本次搜索。

## 相册检查与加载

检查范围：当前用户的主共享存储。先读 DCIM、Pictures、Movies，再查其他可访问的目录（包括 Download、自定义目录和 Android/media）。不查 Android/data、Android/obb、其他用户或存储卷、子目录链接和特殊文件。按扩展名识别照片和视频，不当作完整的系统媒体库。

进入相册：

| 情况 | 结果 |
| --- | --- |
| 首次进入，没有暂存 | 开始检查，分批显示已发现的媒体和已检查数量 |
| 同一设备有可用暂存 | 直接恢复上次的结果、检查时间和滚动位置 |
| 上次离开时还在检查 | 以「已停止」状态恢复上次的结果 |
| 用户点「刷新」 | 开始新检查；期间继续浏览旧结果，新结果可用后点「更新照片」才替换 |

- 选中或打开时固定对象和浏览位置。
- 离开后再进入，仍可点「更新照片」采用离开前得到的新结果。
- 点「更新照片」后整批替换为同一次检查的完整结果；范围面板关闭后保持原浏览位置。
- 停止或离开页面时，保留已检查范围内的结果。部分目录读取失败或到达上限时，保留已读到的媒体。
- 到达检查上限时，显示「只检查了部分文件夹」。有限范围内没有结果时，说明还有目录没查。
- 所有结果进入同一个相册列表，缩略图随滚动读取。当前交付差异见[能力边界](compatibility.md#当前交付边界)。

排列和打开：

- 按文件修改日期分组；组内按修改时间从新到旧，时间相同按路径。没有有效修改时间的归入「日期未知」。
- 缩略图不是原件；设备或来源变了不复用旧缩略图。缩略图读取遇到设备忙时有限次自动重试，其他失败由用户手动重试。
- 点图片：进入原件预览。点视频：相册里只显示缩略图，点按进入文件详情，提供可用的取回、分享和在手机上打开。

相册底栏：

- 底栏上方单独显示已加载数量和检查范围。
- 底栏有「刷新」「选择」。选择后同一位置显示「取回原件」；关闭选择后恢复浏览底栏，浏览位置不变。

## 手动传输、冲突与中止

- 主控与手机双向手动传输，保留目录层级、空目录和零字节文件。
- 用户选择文件或从外部分享时，必须明确目标设备和目录。只读取本次授权的内容；来源丢失时要求重新选择。
- 每条待处理的外部分享单独结束。重新进入页面不会重复弹出或重复发送；迟到的回执不影响新的分享。

外部分享的来源：

- 收到的内容先完整复制到本机受保护的位置，确认写完后才可以发送。复制没完成时，不显示来源可用。
- 关闭分享页、结束这条分享或删除历史，都不会解除已提交传输对这份副本的保护。只有使用它的所有传输都结束后，才回收这份副本。

各平台的目录导入和系统保存：Android 使用系统授权的目录；桌面使用系统的路径选择框；iOS 提供当前已交付的选取和保存方式。

同名冲突：

- 询问「保留两份」「替换」或「跳过」，显示两端路径。
- 用户的选择只用于本次任务。

停止和重试：

- 停止按钮放在任务旁。等待停止确认期间，原任务仍可查看。
- 逐项重试时重新核对并从头传输；写入结果未知的，先核对。
- 收到回执后显示实际阶段。目标目录在最后一批写入结束后自动刷新，无论结果是完成、失败还是取消。

### 传输列表

全局「传输」页，每个批次一条任务，分两个页签：

| 页签 | 包含 | 排序 |
| --- | --- | --- |
| 「传输中」 | 等待、正在传输、需要处理、待核对 | 最近更新在前 |
| 「已结束」 | 已核对的已完成、部分完成、传输失败、已取消 | 结束时间在前 |

- 任务结束后自动移到「已结束」。结束时间来自任务日志；旧记录没有时间时不显示时间。
- 每条显示文件名或批次名、方向、来源和目标。单张图片有缩略图时显示缩略图，其他文件按格式显示图标。
- 页签在列表上方，切回时恢复该页签的滚动位置。
- 进行中显示已确认传输的字节数；总量已知时同时显示进度条和百分比。等待用户决定或核对时，显示实际阶段和原因。
- 点任务进入详情，逐项查看文件和结果。原件准备期间离开页面，仍可在这里查看。编辑后的副本由用户手动传回手机。

清空记录（只在「已结束」）：

1. 点「清空记录」，确认后移除该页签的全部历史。
2. 手机原件、本机已保存的文件和已取回的暂存原件都保留；进行中或等待处理的任务留在「传输中」。
3. 取消确认：回到原列表。清空后停留在「已结束」，显示空态。

## 原件取回与系统交付

原件完整取回、校验通过、且暂存仍可用后，才提供打开、保存和分享。准备过程显示真实进度，可以取消。

文件详情和图片预览的底部有「取回文件」和「分享」。图片预览还可在同一栏切换「原尺寸」和「适合屏幕」。

取回单个文件：

1. 点「取回文件」，下载原件并校验。
2. 完成时如果发起页面仍在前台，直接打开主控系统的「打开方式」选择器，候选应用由系统根据格式和已安装应用决定。已离开原页面时，可以从本次传输记录打开选择器。
3. 取消选择器：回到原页，已取回的文件保留；再次打开复用同一份暂存原件。
4. 系统没有能打开的应用或选择器不可用时，显示原因和可用的保存或分享入口。

批量取回保留逐项结果，每个文件由用户选择后再交给系统。

[Android 系统选择器](https://developer.android.com/guide/components/intents-filters#ForceChooser) · [Apple Open In 菜单](https://developer.apple.com/documentation/uikit/uidocumentinteractioncontroller/presentopeninmenu%28from%3Aanimated%3A%29)

分享：

1. 点「分享」，在同一次操作内准备并校验原件，然后打开系统分享面板。
2. 取消准备或取消分享：回到来源页。失败时在原任务显示原因和恢复操作。
3. 系统确认分享已取消时，可以直接再次打开分享面板。已经选了接收应用或结果待确认时，先到接收应用里核对，再决定是否重新分享。

当前实现与上述目标的差异见[能力边界](compatibility.md#当前交付边界)。

各阶段完成时的含义：

| 完成点 | 含义 |
| --- | --- |
| 原件取回 | 完整原件已在主控的私有暂存里，还没有保存到系统位置 |
| 系统打开 | 文件已交给主控系统的打开方式选择器，由系统决定可用的接收应用 |
| 系统保存 | 已写入目标、关闭文件并核对结果；不保证已同步到云端 |
| 系统分享 | 已交给接收应用；不保证它已读取、保存或发送 |

- 界面区分手机原件、本机暂存、系统副本（或接收应用）三者。待核对时提供检查入口。
- 取消选择保存位置：原件保留。写入后才取消：检查并说明已经存在的副本。
- 离开页面时，结束该页仍在执行的文档操作。
- 全部跳过时显示「未保存」；只写入了一部分时，显示已保存的范围。

### 系统保存的安全边界

- 新文件只用独占创建（目标存在就失败），不覆盖已有文件。
- 目标已有内容时，提供「保留两份」「跳过」或「取消」。只有系统支持可核对的原子替换时，才提供「替换」。
- 写入单个文件时，目标必须是已核对的空普通文件，并支持定位和同步。管道、非空文件和失效的授权，给出拒绝原因。
- 结果未知时保留目标，先核对再处理。
- 取回文件时，先写完本机暂存，再开放原件。暂存位置明确拒绝写入时，说明原因并允许重试；结果无法确认时，提示先核对目标。

### 保存记录与未知结果

- 提交前先把保存记录可靠写入本机。无法读写或容量不足时拒绝新任务，不挤掉旧记录。
- 离开页面、换设备、重新进入或重启应用后，已保存和结果未知的记录都保留。
- 重新进入时先只读核对：已保存过的文件要再存一份，需要用户确认；结果未知的，由用户到文件应用里核对后明确选择继续。
- 中断时保留待核对状态和暂存。迟到的回执不覆盖其他操作或已经结束的结果。记录不恢复系统授权。

## 媒体暂存与空间准入

媒体暂存是主控上存放取回原件、预览大图、分享副本的私有空间。

- 默认上限 512 MiB。其中的文件分三种：准备中、受保护、可回收。不包括手机原件、用户保存到系统的文件和系统分享副本。
- 新的准备先回收旧的可回收项；仍不够就拒绝，不覆盖正在使用的文件。

空间检查：

- 取回、预览大图、分享或接收前，检查本次所需空间和实测可用空间。不够时显示「需要 X，当前可用 Y」，并按情况提供清理、减少所选文件或在手机上打开。
- 大小未知时边读边检查，在超出上限前停止。
- 空间不足只影响本次操作：原文件保留，其他设备的功能照常。

文件保护：

- 预览、传输、准备、保存和结果待核对期间，对应的暂存原件受保护。
- 刷新时为新读取单独创建一份副本。
- 交给外部应用的文件，在能确认对方的读取期限之前一直保留。

暂存页：

- 用一组列表行显示总占用，以及可回收、受保护、准备中各自的实际占用。
- 列出每个受保护项的文件名、来源、保护原因和可执行操作。
- 全部占用都受保护时，显示「当前没有可清理项目」，不显示看似能释放空间的按钮。
- 保存到系统位置和释放暂存是两件事：保存成功不代表外部应用的读取保护已解除。

清理：

- 列出可回收的项目，用户确认后报告实际释放的空间。
- 已被清理的原件，需要重新取回后才能保存或分享。受保护项可以另存到系统位置；已交给外部应用的文件仍保留。
