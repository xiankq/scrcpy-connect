# 信息架构

## 设备优先

设备列表是固定首屏，没有主力、备用或附属设备角色。用户先选择设备，再进入它的工作台、应用、内容和通信。全屏远控用远端画面表达来源；其他远端页面保留设备名称和操作对象。

全局导航只有三个目的地：

| 目的地 | 任务 |
| --- | --- |
| 设备 | 查看、添加和连接设备，进入设备工作台 |
| 传输 | 查看跨设备任务、进度、冲突、失败和可恢复事项 |
| 设置 | 管理外观、后台保持、全局授权密钥和本地数据 |

设备列表的状态、搜索、连接菜单和表单入口见[设备连接](device-connection.md)。任何已保存设备都可进入同一工作台，恢复记录不等于恢复授权。

## 设备工作台

工作台以设备为中心：顶栏显示名称，首卡摘要进入只读设备数据页；“快捷操作”提供文件、相册、通知和通话；“活跃应用”只列当前设备仍保留的真实应用任务；“全部应用”进入完整应用列表与搜索。

活跃应用按包名去重，包含暂在后台的真实任务，不混入仅已安装应用。应用名和图标来自当前被控用户；读取失败显示中性缺失标识，不代替成主控图标。无法读取任务时分别表达检查中、失败和平台受限，不把未知当作空列表。

设备设置、连接能力、当前活动和管理的具体归属见[设备连接](device-connection.md#设备工作台)。文件、相册、通知和通话是快捷入口；连接、通知、传输、声音和通话是不同活动，不能用一个全局页面混列所有设备状态。

## 设置与本地数据

全局设置提供外观、后台保持、全局授权密钥、媒体暂存、运行日志和本地数据管理。设备名称、连接配置、画面设置和当前活动留在对应设备，不在全局设置重复。授权身份规则见[设备连接](device-connection.md#授权密钥)，媒体暂存与空间准入见[内容与传输](content-and-transfer.md#媒体暂存与空间准入)。

外观只提供浅色、深色和跟随系统；文字缩放、减少动态效果和降低透明度遵循系统设置。系统保存、原件暂存和手机原件是不同对象；删除传输记录不删除用户文件，清理暂存也不删除远端原件。

运行日志默认在本机记录启动、连接与播放故障，以及播放器报告的实际解码后端；日志有容量上限，自动轮转，不自动上传。用户可按级别和来源查看、导出全部保留日志，或确认后清空；清空后继续记录。日志不包含授权密钥、配对码、剪贴板、通知正文或媒体访问凭据。平台解码 API 名称不能证明实际硬件加速，未证实时显示状态未知；平台确认实际组件或硬件帧后才显示硬件解码，明确的软件后端显示软件解码。日志保留可识别的实际组件和纹理准备路径，仅记录首次准备或路径切换；纹理已准备不表示已完成界面合成或屏幕显示。

## 手机、平板与桌面

手机一次聚焦一个主要工作区，通过底部导航切换设备、传输和设置。导航支持点击和横向拖动，触点反馈与已呈现目的地保持一致；辅助偏好变化后仍保留标签、焦点和操作能力。

大屏使用侧栏和单一当前内容区，不整体缩放手机稿。内容按实际可用空间布局，手机列表不直接变成窄侧栏。多个远控窗口并行是能力目标；现有布局稿和侧栏实现不证明应用、文件与传输已经能同时并排操作。

## 功能支持状态

| 状态 | 呈现与下一步 |
| --- | --- |
| 未知 | 显示检查中或尚未检查，不承诺可执行 |
| 需要设置 | 说明缺少的设置、在哪台设备完成以及如何继续 |
| 可用 | 提供操作并反馈实际结果 |
| 受限 | 说明可完成部分与限制，保留替代入口 |
| 不可用 | 解释原因，避免循环引导无效设置 |

已配对、当前连接和单项功能可用分别呈现。一个扩展功能受限不能阻断其他入口；无法核验时保留未知和检查入口。
