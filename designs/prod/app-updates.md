# 应用版本与更新

设置里的「关于与更新」显示已安装的版本，用户可以检查新版本、查看更新记录，并通过安装渠道完成更新。

当前已交付：

- 显示实际安装包的版本号和构建号；读取失败时说明原因。
- 「检查更新」：从发布渠道读取版本清单。发现新版本时弹出「发现新版本」弹窗，按钮为「稍后」和「前往发布渠道」。
- 「更新记录」。
- 「关于」和「开源许可」。

下文的自动检查、应用内下载与安装是目标行为，渠道验证通过后才提供，见[渠道交付](#渠道交付)。

## 更新记录

- 按发布日期从新到旧排列，标明已安装的版本，显示每个版本的发布说明。
- 更新弹窗只显示目标版本的摘要，可以从弹窗进入更新记录查看完整说明。

## 检测与提醒

手动检查：在「检查更新」这一行显示正在检查、「已是最新版本」或失败原因与重试。

自动检查（目标）：

1. 应用回到前台后，可以从当前安装渠道检查与这台主控兼容的版本。
2. 同一个目标版本第一次确认可用时，弹出「发现新版本」。
3. 用户正在远控、通话、提交表单或处理其他弹窗时，不弹窗，只在设置里保留更新入口，等合适的时候再提示。
4. 选「稍后」后，本次前台期间不再自动弹出；仍可在设置里手动打开。
5. 检查失败时，保留上次确认的信息并注明时间。

更新提示的内容：当前版本、目标版本、已知的安装包大小、本次更新内容。只对当前安装渠道已确认可用、且与这台设备兼容的版本提示。更新来源、兼容性和完整性由对应渠道验证。

## 下载、校验与系统安装

以下是支持应用内下载的渠道上的目标流程。

| 状态 | 页面显示与操作 |
| --- | --- |
| 发现新版本 | 版本和更新摘要，「下载更新」「稍后」 |
| 准备下载 | 真实的连接或等待状态；进度未知时用线弧表示 |
| 正在下载 | 按实际收到的字节显示进度。总量已知时显示百分比和大小，未知时显示已下载量和等待标记 |
| 正在校验 | 收到完整安装包后，按渠道核对完整性和能否安装。可以收起弹窗，设置里保留本次更新入口 |
| 已下载 | 渠道确认可以安装后，显示「安装更新」「稍后安装」。点安装时说明需要退出或重启应用；有正在使用的画面、通话或传输时，先列出会受影响的任务 |
| 正在打开安装程序 | 用户确认后交给系统安装界面。回到应用后核对实际安装的版本，再更新「当前版本」和安装标记 |
| 下载、校验或交付失败 | 保留目标版本和更新说明，显示实际原因和可用的重试 |

- 收起弹窗后，下载是否继续取决于渠道；设置里显示可以继续查看的更新状态。
- 支持取消的下载，在弹窗里提供「取消下载」。
- 回到前台或重新进入更新页时，先恢复渠道报告的当前状态，再开放对应操作。
- 同一个目标版本只下载一次。在系统安装界面取消后，按渠道重新核对；仍可安装时保留「安装更新」。

## 渠道交付

- 由商店或系统接管更新时，弹窗提供「前往商店」或对应的渠道入口，下载和安装进度由渠道显示。
- Google Play 弹性更新：拿到进度回执时，可以在应用内显示下载状态；下载完成后由用户确认安装或重启。
- App Store 分发：遵循商店更新。
- 桌面应用：按实际安装渠道进入系统更新或受信任的安装程序。
- 每个渠道单独验证后，才显示它支持的操作。

[Google Play 弹性更新](https://developer.android.com/guide/playcore/in-app-updates/kotlin-java#flexible) · [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) · [Windows App Installer 更新设置](https://learn.microsoft.com/en-us/windows/msix/app-installer/update-settings)

Windows 安装向导：随应用安装内置 ADB，支持离线安装。首次安装时，创建桌面快捷方式的选项默认不勾选。

## 构建渠道配置

- 正式版用 `--dart-define=APP_UPDATE_FEED=<HTTPS 地址>` 指定更新清单地址，从 GitHub 最新 Release 下载稳定版清单。
- Android、Linux、Windows 和已启用签名渠道的 macOS 共用一份清单，用户在版本页面上选择自己的平台。
- 清单是 JSON 数组，每条包含：稳定版 `version`、整数 `build`、ISO 8601 格式的 `publishedAt`、字符串数组 `notes`、HTTPS 渠道入口 `url`，可选的安装包大小 `bytes`。
- 兼容性筛选和安装由发布渠道负责。
- 公开预览版和试打包构建没有配置清单地址，「检查更新」处显示渠道尚未配置。
- 开源许可页同时列出项目许可和 FFmpeg 署名。
